## 1. Purpose

Vision §59 asks whether experiments written against MockRadio run on a USRP by changing only the BindingProfile. This Module is the other side of that comparison: it implements spec 07 on an X310 as MockRadio implements it in simulation, reports what the device does through the same events, flags and records, and declares what it cannot promise. It is written so that everything except the device itself runs without hardware: the Provider's logic talks to a `Device` trait, and the tests drive it with `FakeDevice`, a double of a USRP whose host clock is the real one by default and the manual one the smoke set selects (UR-2, UR-33), through the real coordinator.

## 2. Evidence

- **UHD's C API is a narrow bridge already** (VERIFIED, UHD 4.10 headers on this Mac, `/opt/homebrew/include`): every C entry point wraps its body in `UHD_SAFE_C`, which catches `uhd::exception`, `boost::exception`, `std::exception` and `...`, stores the text for `uhd_get_last_error` and returns a `uhd_error` code (`uhd/error.h:89-104`). Handles are opaque pointers, structs are POD (`uhd/types/metadata.h`, `tune_request.h`, `usrp/usrp.h`). This is what Vision §35 asks the bridge to be. **The functions and structs UR-2 and UR-3 add** — `uhd_subdev_spec_{make,free}`, `uhd_usrp_set_{rx,tx}_subdev_spec`, `uhd_meta_range_{make,free,size,at}`, `uhd_usrp_get_{rx,tx}_rates`, `uhd_usrp_get_{rx,tx}_antenna`, `uhd_usrp_get_rx_info` with `uhd_usrp_rx_info_free`, and `uhd_range_t` and `uhd_usrp_rx_info_t` — are declared in those headers, at the layouts `uhd_api_struct_sizes_match_the_headers` records (UHD 4.10.0's `usrp/usrp.h`, `types/ranges.h`, `types/usrp_info.h`; checked against the bench image's copy of the same headers).
- **Receive metadata codes** (VERIFIED, `uhd/types/metadata.h:80-92`): `NONE 0x0`, `TIMEOUT 0x1`, `LATE_COMMAND 0x2`, `BROKEN_CHAIN 0x4`, `OVERFLOW 0x8` (with `out_of_sequence` distinguishing a sequence error), `ALIGNMENT 0xC`, `BAD_PACKET 0xF`. **Asynchronous transmit codes** (`:232-244`): `BURST_ACK 0x1`, `UNDERFLOW 0x2`, `SEQ_ERROR 0x4`, `TIME_ERROR 0x8`, `UNDERFLOW_IN_PACKET 0x10`, `SEQ_ERROR_IN_BURST 0x20`, `USER_PAYLOAD 0x40`.
- **Timed commands** (VERIFIED, `uhd/usrp/multi_usrp.hpp`, `set_command_time`): "A timed command will back-pressure all subsequent timed commands … If the time spec is late, the command will be activated upon arrival." The device neither refuses a full queue nor reports a late command: the Provider must count and judge both itself (UR-24).
- **Setting device time** (VERIFIED, `set_time_unknown_pps`): "a 2-step process, and will take at most 2 seconds", and "when changing clock sources, a previously set time will most likely be lost … set the time after changing the clock source". v3 sets the clock source, then the time source, in that order (`v3/cpp/uhd_usrp/multiusrp.cpp:332-347`, cited by the spike).
- **Sensors** (VERIFIED, `uhd/usrp/usrp.h:448`, `uhd/types/sensors.h:55-121`): `uhd_usrp_get_mboard_sensor` and `uhd_sensor_value_to_bool` read `ref_locked`.
- **Alignment** (VERIFIED by Phase 4 Review D in UHD master `0d7ed3b`, `rx_streamer_impl.hpp`, `get_aligned_buffs.hpp`): an alignment failure yields no samples, or only aligned ones, and discards packets whose timestamps disagree; never a partial channel set.
- **Overflow**: UHD restarts a continuous stream `OVERRUN_RESTART_DELAY` = 0.05 s after an overflow (VERIFIED, audit Finding 3; MR-3).
- **The X3xx values** of `ezsdr_radio::x3xx`'s description, which both Providers build (design 33 D5), with the sources MR-3 marks (spec 09 §2).
- **The spike** (`spike/uhd`, VERIFIED on its fake device and against libuhd with no device): the C API slice of ~40 functions, the anchor-and-extrapolate Authority, the thread structure, and findings K1–K13.
- **INFERRED** (checked on the bench, `bench.md`): the device lead, the delivery allowance, the per-direction start leads, the in-flight window and the release window of §3; how many timed UBX commands the device's queue holds before it back-pressures (UR-24); which UHD errors mean a lost device (UR-29); the drift bounds of UR-8; and every INFERRED value of UR-9. **Measured on the bench and applied** (design-notes §11, the owner's decision of 2026-09-30): the X3x0 ignores the time of a continuous receive stream's stop and stops at once (VERIFIED: UHD 4.10's `radio_rx_core.v` and `hw_b8_raw_rx_timed_stop`), so UR-25 hands the device no timed stop; the X300 drops a timed start-of-burst at the tick its previous burst ended (`hw_b8_raw_burst_gap`), so UR-23 continues the device burst there.

## 3. Model

```text
                         runtime (server catalogue / test assembler)
                               │ open(args) ──► Arc<dyn Device> ◄── FakeDevice::new(..) (tests only)
               ┌───────────────┴────────────────┐
         DeviceAuthority (Authority)        UhdRadio (Provider, not stepped)
         root = device master clock           │ prepare: apply, verify, declare clocks
         now = anchor + host elapsed          │ arm: streamers, transmit clock on the lattice
         uhd-clock: re-anchor every 100 ms    │ start(T0): receive clock at T0, timed start
         next_wakeup: nap ≤ 20 ms             │
                                              │
            threads:  uhd-control ── ActionReceiver (MA-14b loop, 1 ms): books Actions, releases
                                     held timed commands, checks reference and device time
                      uhd-rx-s<k> ── one per declared receive stream (design 33 D15, D4), owning
                                     that stream's streamer: recv → blocks → its port's links;
                                     RX_OVERFLOW on the hot path; performs its switches; idle
                                     while its stream holds no channel
                      uhd-tx-s<k> ── one per declared transmit stream, owning that stream's
                                     streamer: bursts in target order → send, BurstTracker;
                                     async reports; performs its switches; idle while its stream
                                     holds no channel

 Kernel side (spec 19): data thread steps the capture Sink (KC-46); KC-21a waits for uhd-control to
 finish a Session's Actions; a DEVICE_LOST from uhd-rx stops the radios at once (MA-9a, KC-46b).
```

A layout instance declares one stream per channel in each direction (design 33 D4) and starts a thread for each whether or not it holds a channel.

A tick of the Run's primary root is one master-clock tick of the device (200 MHz). Every SampleClock is `root_ticks_per_tick = N` for the device's integer decimation `N` (UR-12).

The Module's own constants, all INFERRED and measured at bench step B8, are: the **device lead** 2 ms (the lead it needs from receipt, UR-21, UR-24); the **delivery allowance** 3 ms (UR-14; the declared lead is their sum, 5 ms); **one start lead per direction**, 50 ms each, the profile's `radio.timing.rx_start_lead_ns` and `radio.timing.tx_start_lead_ns` (UR-9, UR-25), whose values the bench measures; the **in-flight window** 10 ms (UR-23); the **release window** 3 ms (UR-24). **Ceiling:** both leads are 50 ms, the value of the constant each replaces, so no test tells the Module reading its profile from reading a constant until the bench measures them.

## 4. Rules

### Identity and the device boundary

- **UR-1** The Module is `ModuleDescriptor { id: ezsdr.radio.uhd, version: 0.4.0, kernel_api: 4.0.0, roles: [Provider, Authority], vocabularies: [{ radio, ^2.0.0 }], impl_hash: Some(ContentHash::of_bytes(b"ezsdr.radio.uhd 0.4.0")) }`, returned by `ezsdr_radio_uhd::descriptor()`; `module_ref()` returns its `{ id, version }`. A runtime registers it with `Factories { provider: true, authority: true }`.
  *Test:* `ur_01_the_descriptor_registers` (the roles, the impl hash and version 0.4.0, and the refusal of a runtime whose `radio` Vocabulary is not 2.0.0).
- **UR-2** Everything the Provider and the Authority do to a device goes through the object-safe trait `ezsdr_radio_uhd::Device: Send + Sync`, whose methods are exactly:

  fn fidelity(&self) -> Fidelity;                    // UR-31
  fn master_clock_rate(&self) -> u64;                // integer Hz

Ticks are master-clock ticks; no floating-point time crosses the trait. Streams are numbered from 0 in each direction, and a call's channels are the device's own numbers under its current subdev spec (UR-3, design 33 D5).

  - `uhd_tx_metadata_{make,free}`;
  - `uhd_async_metadata_{make,free,channel,has_time_spec,time_spec,event_code}`.

  These are used with the structs `uhd_stream_args_t`, `uhd_stream_cmd_t`, `uhd_tune_request_t`, `uhd_tune_result_t`, `uhd_range_t` and `uhd_usrp_rx_info_t`, laid out as the UHD 4.x headers lay them out. Every call's `uhd_error` other than `UHD_ERROR_NONE` becomes `DeviceError { lost, message: "<call>: UHD error <code>: <text>" }`, the text read from the handle the call was made on — `uhd_usrp_last_error` under the control-call mutex, `uhd_{rx,tx}_streamer_last_error` under the streamer's call mutex — and from `uhd_get_last_error` for a call on no usrp or streamer handle (the meta-range and subdev-spec calls included). A streamer value owns its handles from their creation and is moved into its `Arc`, and an open releases that stream's old streamer before it makes the new one, so a refused reopen leaves the stream with none. A call naming a stream no streamer is open for fails at once, and `tx_async` finds no report at once. `set_subdev_spec` frees its spec handle whether `uhd_subdev_spec_make` succeeded or not (`subdev_spec_c.cpp:31-36`). Streams are `fc32` on the host and `sc16` on the wire, so `radio.perf.wire_bytes_per_sample` is UR-9's. `serial` is `uhd_usrp_get_rx_info`'s `mboard_serial` of channel 0 (INFERRED).

  **Time conversion** (TM-20): a tick `t` is sent as `full = t.div_euclid(mcr)`, `frac = t.rem_euclid(mcr) as f64 / mcr as f64`; a time spec `(full, frac)` is read as `full · mcr + round(frac · mcr)`, rounding to nearest, ties away from zero, with `checked` arithmetic (an overflow is a `DeviceError`); a tick converted to a time spec and back is the same tick for every tick in `0 ..= 2^53` (`rem < mcr < 2^28`, so the round trip is exact). `open` refuses a device whose master clock rate is not a positive whole number of hertz.

  **Threads.** The handles are shared by the Module's threads under two rules: every **control call** (`apply` with its `set_command_time`…`clear_command_time` bracket, which is per-motherboard state; `set_subdev_spec`, `rates` and `serial`; `set_sources`, `set_time_zero`, `time_now`, `ref_locked`; and the timed stream commands of UR-15, UR-17 and UR-25) is made under one `UhdDevice` mutex, and a time read used for an anchor or a relation takes its host brackets around `Device::time_now`, which takes the mutex inside, so that a read that waited for the mutex is widened and UR-7's 1 ms rule discards it (the `Device` trait has no bracketed read);

  and each **streamer** has one owning thread at a time — its uhd-rx thread owns a receive one (`recv`, the stream commands, and a reopen, UR-25) and its uhd-tx a transmit one (`send`, `recv_async_msg`, and a reopen; design 33 D15) — except for the stream an enable from no stream gives uhd-control until its booking, or until the enable ends without one, and the report read the transmit shutdown makes after the join bound left uhd-control detached (UR-25, UR-16) — each kept alive by an `Arc` its owner holds, so that `close_streams` frees only a streamer no thread holds (UR-16). The safe `Device` methods enforce exclusive native access with a separate mutex on each streamer, held through the call and all metadata/error-text reads; receive stream commands share that receive streamer's mutex, and transmit sends and asynchronous reports share their transmit streamer's. Construction and final drop have exclusive handle ownership. `UhdDevice` is `Send + Sync` on that enforced basis, stated at its `unsafe impl` (INFERRED from UHD's documented `multi_usrp` thread safety).

  *Test:* `ur_03_time_specs_round_trip` (the conversion functions live outside `uhd.rs`, so the default build runs it: the tick round trip at `0`, `1`, `199 999 999`, `200 000 000`, `2^53` and `−1`, and the overflow refusal), and with the feature `uhd_api_find_returns`, `uhd_api_open_of_an_absent_device_is_an_error_with_uhd_s_text` (the `<call>: UHD error …` text), `uhd_api_struct_sizes_match_the_headers`, `uhd_api_a_streamer_is_freed_once` and `uhd_api_a_refused_subdev_spec_is_freed_once` (against real libuhd: the refused markup's own call name and UHD's text, while the free itself has no witness there), and `uhd_a_subdev_spec_is_freed_once_on_every_path` (feature `uhd`, in `src/uhd.rs`, whose make, set and free calls are replaced for that test binary: one free per path — after the set, the handle a refused make had allocated before it parsed, and a failed set's), and `uhd_streams_are_looked_up_by_number` (the streamer map, a call on a number with no streamer, and each streamer's own channel count and packet size); none named for the declared-function list, the per-handle last-error choice, the mutex and control-call rules, the wire format or the master-clock refusal.
- **UR-4** `ezsdr_radio_uhd::open(args: &str) -> Result<Arc<dyn Device>, String>` opens the device UHD's device string `args` names (`uhd_usrp_make`). Built without the feature `uhd` it returns `Err("ezsdr.radio.uhd: built without UHD (feature `uhd`)")`. It never returns a `FakeDevice`, whatever `args` says. A runtime calls it once per binding, and the Provider and the Authority built from that binding share the returned object (UR-6).
  *Test:* `ur_04_open_without_the_feature_refuses` (the build without the feature) and `ur_33_no_document_selects_the_fake_device` (`open("fake")` and `open("type=fake")` refuse, and the selector key `fake` is refused).

### Construction and the Authority

- **UR-5** `UhdRadio::from_binding(binding: &Binding, device: Arc<dyn Device>) -> Result<UhdRadio, ModuleError>` refuses with `Rejected`: a `module` other than UR-1's; a `profile` other than `x3xx` 0.1.0 (absent is refused); a `feed`; a selector key other than the ones below, or one of the wrong kind or out of range; every refusal `ezsdr_radio::channels::from_selector` makes of the shared keys (a missing, malformed or repeated-pair layout among them; design 33 D5); a `serial()` that fails, and a device whose serial a live `UhdRadio` still holds (reason naming it); a device whose master clock rate is not the profile's master clock (UR-9) (reason `"UR-5: profile x3xx needs a 200 MHz master clock; the device runs at <n> Hz"`); and a device whose front end on one of the layout's channels `Device::front_end` names otherwise than that element's board (`UBX…`, `OBX…` or `CBX…`, as UHD names them: `UBX RX`, `OBX TX`, `CBX-120 TX`; reason `"UR-5: the layout's <rx|tx> channel <c> is `<name>`, not `<board> front end <n>`"`). The layout decides the channels and the boards; the module-specific keys are the Module's own (UR-9).
 The opening checks run in one order: `serial()`, registered for the instance's life (UR-5, design 33 D5); the master clock; each direction's subdev spec — `<slot>:<front end>` per element in its order, one ASCII space apart, and none for a direction with no element (H2); then `front_end` on the layout's channels, whose names are checked against the elements (a Basic/LF board down to its front end's number, `BasicRX (1)`). A `set_subdev_spec` the device refuses is refused with UHD's text — a device with fewer channels than the layout names included —, and a spec is set before any front end is read (H1).

  UHD clips a tune to the front end's range widened by the DSP's reach (min(DSP range, bandwidth / 2), `multi_usrp_utils.hpp`) without a warning and reports it in `tune_result.clipped_rf_freq` and the read-back, which UR-12 records but does not refuse. A real X310 with one CBX in slot A and slot B empty reports 2 + 2 channels, channel 0 the CBX and channel 1 UHD's unknown board (`db_unknown.cpp`), so only the layout's own channels are checked:

### Receive

- **UR-17** uhd-rx carries out the receive plan it shares with uhd-control (UR-25), reading it at every turn. It calls `rx_recv(k, block_len, 100 ms)` in a loop, asking for no more than up to a pending cut. It takes as the cut the later of the cut it was given and the first sample it has not delivered, discards samples at or after that cut, and stops the stream untimed once its samples reach it or it has been silent past it for one block plus §3's delivery allowance, recording the stop in `applied` with the cut and the instant it was issued, and ends the clock at the cut.
  Its source is `<id>/rx/s<k>` (RM-29). For the next segment it reopens the streamer unless the device record holds its channel set, configures the stream with the configuration in effect at the origin (UC-2's projection, held timed commands included) unless the record holds the segment's set and its command (UR-36), issues a timed start there once configured, and registers the clock at its first block (RM-25). Its turns while an enable from no stream holds the stream are UR-25's. When a cut cancels a segment whose timed start is already issued, it stops the stream untimed only after that origin has passed, discarding what arrives; a cut at or before the first sample not yet delivered, once the origin has passed, stops and ends the stream at once.
  A configuration UR-12 refuses halts its stream (RM-25), with `COMMAND_REJECTED` and UR-12's reason: uhd-rx books the change as refused itself, and then begins the plan's next segment, which may begin where the refused one would have.
  uhd-rx keeps, in its stream's phase while it is active, the first sample of its segment not yet delivered (even when the plan no longer has the segment it began), where a booking reads it, updated with the cut it reads for each block: a loss and `Provider::stop` are booked with it (RM-16's floor, `Item.delivered`), so under `abort` the plan cuts the running segment there, and uhd-rx ends it at once; once `Provider::stop(abort)` has begun, uhd-rx ends a segment still being delivered up to an earlier cut there too, as soon as it reads the plan; and the end takes that sample only for the segment it cuts, still running at the end. Once the device is lost it reads the plan again and ends the stream at the loss's cut, which the thread that found the loss booked under the plan's lock before any thread can find the device lost. When a segment ends, the timeline's items before the command that began it are pruned.

### Transmit

- **UR-21** uhd-control refuses a `TxBurst` with `radio.COMMAND_REJECTED` when RM-13 refuses it, and, as this Module's own, when its `at` is not on its target stream's last registered transmit clock, or when the waveform's bytes are not an input of the Run or their length is not `size_bytes`.   Otherwise uhd-control decides the burst as RM-14 says, with §3's device lead, and hands a held burst to uhd-tx.
  Before its first timed start-of-burst hand-over, uhd-tx repeats the device-lead decision against its current instant, as RM-14 says; an adjacent continuation of an already open device burst has no timed start and follows the preemption rule instead.

- **UR-22** uhd-tx transmits a burst by sending its waveform with start-of-burst and the time spec of its start; a burst without `repeat` ends with end-of-burst on its last samples. A burst ends at the end of its waveform (without `repeat`), at the start of the next held burst as UR-21 decided it (the current one is sent up to the sample before the next start), at a `Stop` for `<id>/tx/s<k>` or `<id>`, at a `cold` transmit change (UR-25), or at the Provider's `stop`.
  **Device bursts.** Where the next burst starts at the current one's next sample — held at that start, or preempting the current one and decided there by UR-21 — the device burst continues: the current one's last buffer goes without end-of-burst and the next one's first without start-of-burst or time spec. The two Kernel bursts keep their own `START_OF_BURST`/`END_OF_BURST` blocks and records, and one `BURST_ACK` answers both.
  A next burst that starts later is a new device burst: the current one's last buffer carries end-of-burst — or, when that buffer already went out, an empty buffer does, so that no timed start-of-burst falls inside an un-ended burst — and the next starts with start-of-burst and its time spec. A Kernel burst's end is not at once the device burst's: while a burst could still be booked at its next sample, its last sample is held back from its last buffer, so that a burst booked there after that buffer went out still continues it; when no burst is booked there by the time that sample is §3's device lead away, or another burst is next, the held sample is sent with end-of-burst, before the device runs dry; when a burst is booked there, it is sent without end-of-burst ahead of that burst's first buffer. ### Parameter updates

- **UR-24** A `hardware_timed` update of `radio.<d>.c<n>.{frequency_hz,gain_db}` (RM-27) to `<id>` takes effect at `e`: `at` converted to the root and rounded up when present, otherwise the current instant plus §3's device lead (UC-6). An explicit deadline that cannot be converted or rounded within the root range is refused with `COMMAND_REJECTED`; it is never treated as an omitted deadline. The command acts on channel `n` alone and takes one queue slot. If its stream does not run channel `n` at `e`, the command is given there on a later segment planned to run that channel and not refused (UR-25); with no such segment it stays held.
  **Holding and release.** uhd-control does not hand a timed command to the device at receipt: UHD's command queue is in order and back-pressures ("A timed command will back-pressure all subsequent timed commands", §2). It holds the command in its own list, ordered by `e`, and releases it — `apply(dir, chan, settings, Some(e))` on every channel it is given on (`set_command_time`, the setting, `clear_command_time`), under the control-call mutex (UR-3) — when `e` is no more than §3's release window ahead. A command's instant is settled at its booking, and never before a command already released there: it is the requested instant floored at the current instant plus the device lead and at the last released instant; an `at` the floor moves is late there, `radio.LATE_COMMAND { key, requested: at, applied: e }` with `e` the settled instant.
  The timed stream commands of UR-17 (a segment's start at its origin, and a restart) are issued by uhd-rx, which owns them, when it performs them, about UR-9's `radio.timing.rx_start_lead_ns` ahead; uhd-rx hands the device no timed stop (UR-25). At each booking the queue depth is the held plus released commands not yet in effect; one additional command that would exceed UR-9's `command_queue_depth` is refused with `radio.COMMAND_QUEUE_FULL { key, depth }` and not applied (INFERRED: whether that many UBX tunes fit the device queue without blocking).

If no channel is in force — because none is assigned or its stream is halted by a refusal (RM-25) — the release gives the command to later segments that will run its channel and are not refused; if none exists, it remains held, and release stops there so nothing behind it is given before its instant. A segment booked meanwhile that holds the channel gives the device the command at `e`; if `e` passes with no candidate, the row becomes the configuration of record and a later segment applies it (UR-12, UR-25). The device queue remains in `e` order, and a command released after `e` applies on arrival. A refusal on release, other than a lost device, records no `applied` row, writes no configuration of record and leaves the command in every projected configuration; a later configure may apply it. A refusal after release does not take it back. `Stop` cancels no command; `Provider::stop` cancels those still held (UR-26).

## 6. Tests

`crates/ezsdr-radio-uhd/tests/fake.rs` runs every case through the real coordinator (`coordinator::start_spec_run` or `connect`) with an Assembly built as the server's catalogue builds it (the capture Sink, the host Link, `DeviceAuthority` and `UhdRadio` on one `FakeDevice`), unless the row says "unit".

The smoke set runs on the **manual** host clock (plan 30 §4.4): the device's time stops while a Provider thread is busy (M1–M7), so host load cannot move it past a deadline — whether that is enough for the mutation shards' load is the close's stress runs to measure. The test-side waits are that same clock (`device.host().sleep`) and the assertions that a Run met a device instant are measured on it; a wall-clock bound remains only as a watchdog, so a test that freezes or deadlocks fails instead of hanging the suite (plan 30 §7): every manual-clock test arms one shared watchdog (`tests/common/watchdog.rs`, included by `tests/fake.rs`, `crates/ezsdr-acceptance/tests/uhd.rs` and `crates/ezsdr-server/tests/protocol.rs`) that aborts the process with the test's name once a generous bound passes, and whose failure to start fails its test at once (`a_watchdog_that_cannot_start_fails_its_test`) (120 s by default, below `mutate.py`'s 180 s timeout; `EZSDR_TEST_WATCHDOG_SECS` raises it, which the load probe does — under oversubscription a test legitimately runs far longer). No short wall interval decides a functional property: where one needs the device's clock to stand still, a participant holds it until the test releases it after its checks (R19–R21).

A test whose point is a real host latency keeps the real clock (plan 30 §4.4): the Authority's own wake-latency diagnostics (`ur_07_schedule_wakes_a_waiting_next_wakeup` and `ur_07_cancel_wakes_a_waiting_next_wakeup`, their medians the only short wall verdicts left; the wakes themselves are pinned on a held clock by unit tests), the monotonic guard across a re-anchor (`ur_07_now_is_monotonic_across_a_reanchor`, whose bracket error is real time's), the intentionally wedged thread, and `ur_33_a_real_fake_s_time_starts_at_its_own_creation` (a device's time measured against the process-wide real clock, R07). GPIO as a sub-resource (Vision §67's advanced peripherals, after the freeze; Vision §39). A wire-format selector (`sc8`, `sc12`). Refining the lost-device error list and the INFERRED leads from the bench (Phase 8).
