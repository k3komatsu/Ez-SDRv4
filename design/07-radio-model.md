## 1. Purpose

Vision §5 puts "channels, streams, RF parameters, TimingEnvelope, PerformanceEnvelope, coherence basis, repeat / decimation capabilities" in the Radio Model, a Vocabulary: versioned on its own, additive, and never read by the Kernel by name (OV-21). This document is that Vocabulary's first version. Every radio Provider — MockRadio (spec 09) and the UHD Provider (spec 18) — implements the same keys with the same meaning, which is what makes Vision §59's "change only the BindingProfile" testable.

## 2. Evidence

- **UHD coerces rate, gain and frequency** to a device grid and documents reading them back (audit Appendix B; spec 03 §2). Hence RM-8's coercion rules and the per-key coercion defaults Vision §11 names: `reject` for sample rate and frequency, `warn` for gain.
- **UHD's overflow**: zero samples returned, `out_of_sequence` distinguishing a host-side sequence error, a continuous stream restarting after `OVERRUN_RESTART_DELAY` = 0.05 s (audit Finding 3, VERIFIED). Hence RM-17 and RM-18.
- **UHD resets the CORDICs on every start of burst and needs a time spec on each** (spec 02 §2). Hence RM-13's one waveform per burst and the Kernel's `BurstTracker` (SC-29).
- **A late timed command** on UHD yields `ERROR_CODE_LATE_COMMAND` on receive and `EVENT_CODE_TIME_ERROR` on transmit (audit §10's UHD row). Spec 04 §9 issue 2 separates the two: `TIME_ERROR` for a burst whose target has passed, `LATE_COMMAND` for a control command issued too late. Hence RM-10.
- **Retune phase** on a UBX or an OBX is random unless the retune is timed (audit Finding 15, VERIFIED against UHD's `page_sync`), and a CBX has no timed LO phase synchronisation at all (`sync_phase` is the UBX's and the OBX's; design 33 D13), so its phase is random on every retune. Hence RM-9's three values.

## 3. Model

```text
Provider instance tree (one per radio instance)
└── <device>                kind radio.device       the node a Spec binds (Y5)
    │   ports:  rx<k>  out  ezsdr.stream.cf32       one per receive channel
    │   capabilities: per-channel, per-stream and instance-wide values
    ├── <device>/rx/s<k>     kind radio.rx_stream    stream id: SampleClock owner, event source
    └── <device>/tx/s<k>     kind radio.tx_stream    stream id: SampleClock owner, TxBurst target

configuration (PrepareReport.effective; per fragment, SB-30)
  radio.{rx,tx}.c<n>.{frequency_hz, gain_db, antenna, stream}
  radio.{rx,tx}.s<k>.sample_rate_hz

instance-wide capabilities
  radio.full_duplex   radio.hardware_time   radio.tx.repeat_*
  radio.rx.block_len   radio.timing.*   radio.perf.*
```

## 4. Rules

### Identity and registration

- **RM-1** The Vocabulary is `VocabularyDescriptor { id: radio, version: 2.0.0, prefix: radio, keys: RM-4's and RM-27's tables, event_kinds: RM-10's table, verbs: RM-12's table, checks: [radio.rf_envelope] }`, returned by `ezsdr_radio::vocabulary()`. `ezsdr_radio::register(registry, checks, kinds)` registers the descriptor, the `RfEnvelopeCheck` of RM-19 and every event kind with owner `Some(radio)`, in that order, and is the only way a runtime assembles the Vocabulary.
  *Test:* `rm_01_register_adds_the_descriptor_the_check_and_the_kinds`.

### Resource tree

- **RM-2** A radio Provider instance exposes one `radio.device` root with `<device>/rx/s<k>` and `<device>/tx/s<k>` children of kind `radio.rx_stream` and `radio.tx_stream`; stream children have no capabilities, ports or memory domains. The root declares one `rx<k>` output port of contract `ezsdr.stream.cf32` per receive channel and its host memory domain. The port name `tx` (direction `in`) is reserved for link-fed transmission and is not declared. A Spec resource that uses a radio is of kind `radio.device`. No node of a radio tree is `shareable`.
  *Producer obligation.*
  *Test:* `mr_02_the_tree_has_the_radio_model_shape`, `rm_29_the_layout_description_builds_the_stream_tree` and `d3_the_layout_is_a_node_id_of_neither_provider`.
- **RM-3** A stream SampleClock is declared on `<device>/rx/s<k>` or `<device>/tx/s<k>` (TM-13a). Its block's `channels` is the size of its channel set, and block channel `i` is that set's `i`-th smallest logical channel (RM-30, SC-10). A stream that holds no channel has no SampleClock or block; every `TxBurst` targeting it is refused (KC-24).
  *Producer obligation.*

  *Producer obligation.*

### Envelopes

- **RM-6** The **TimingEnvelope** is the seven `radio.timing.*` capabilities, each declared on the device node as `One(Int(v))`, in nanoseconds or, for the queue depth, commands: the minimum timed-command lead, the startup latency, the queue depth, the release window, the overflow restart gap and one start lead per direction. A radio Provider sets `ProviderInstance.min_command_lead` to `Some(Duration(host.monotonic, radio.timing.min_timed_command_lead_ns))` when that value is positive and to `None` when it is 0 (MA-10). A Spec expresses a timing requirement as a constraint on these keys; the generic matcher refuses a Provider that cannot meet it at `validate()` (Vision §13 rule 2). The `min_timed_command_lead_ns` is the end-to-end lead the Provider needs from the coordinator's dispatch, including its delivery allowance.
  *Producer obligation.*
  *Test:* `mr_03_profile_values_reach_the_capabilities_and_the_envelope_section`, `ur_09_profile_values_reach_the_capabilities_and_the_envelope_section` and `sb_06_constraint_match_table`; `ProviderInstance.min_command_lead` (`Some` for a positive lead, `None` for 0) by `mr_04_instance` and `ur_10_instance`.
- **RM-7** The **PerformanceEnvelope** is the three `radio.perf.*` capabilities. A layout configuration is admissible only when the sum, over streams in each direction, of channel count × stream rate × wire bytes per sample does not exceed that direction's throughput limit (RM-32). A radio Provider refuses an inadmissible configuration in `coerce`, in `prepare`, and when an admitted `UpdateParameter` takes effect (RM-10, MR-18).
  *Producer obligation.*
  *Test:* `mr_06_coerce_cases`, `mr_18_a_scheduled_pair_is_checked_when_it_applies`; the `prepare` refusal by `mr_07_prepare_cases`.
- **RM-8** **Coercion.** A numeric configuration key is coerced to its declared grid: the sample rates the device node declares as `AnyOf`, and each channel's frequency and gain to multiples of that channel's `radio.d.c<n>.frequency_step_hz` and `radio.d.c<n>.gain_step_db` within its declared ranges (RM-27). For an `Eq(v)` constraint the applied value is the grid value nearest `v`, the lower of two equally near; a `Coercion { key, requested: v, applied, reason }` is recorded exactly when `applied ≠ v` numerically (SB-6). A value outside the range is not coerced into it: the key is `rejected`. For `Min`, `Max`, `Range` and `Set` constraints the applied value is, respectively, the smallest grid value at or above the bound, the largest at or below, the smallest inside the range, and the first member of the set on the grid; none existing is a rejection, and none of these is a coercion. `Present` takes the default.
  A layout description coerces its channel and stream keys by the same rule (RM-30).
  *Producer obligation.*
  *Test:* `mr_06_coerce_cases` and `rm_30_coerce_cases`; none named for the `Max` and `Range` applied values and for a `Min`/`Max`/`Range`/`Set` that finds no grid value.

### Coherence

- **RM-9** A layout description declares `radio.d.c<n>.phase_behavior_on_retune` per channel as `deterministic`, `random_unless_timed_tune` or `random` (RM-27, Vision §26). It declares no direction-wide coherence key.
  *Producer obligation.*
  *Test:* `mr_34_a_random_phase_is_redrawn_by_every_tune`, `d3_a_cbx_layout_is_not_coherent_on_either_provider`; the `deterministic` value by `rm_29_the_ideal_layout_builds_its_tree_and_defaults` and `mr_34_the_deterministic_profile_keeps_every_phase_zero`.

### Events

- **RM-10** The event kinds are exactly these, registered with owner `radio` (RS-27):

  | Kind | Severity | Default reaction | Emitted when |
  |---|---|---|---|
  | `radio.RX_OVERFLOW` | warning | mark_artifact | a receive overrun or sequence error lost samples (RM-17, RM-18) |
  | `radio.TX_UNDERFLOW` | warning | mark_artifact | a transmit stream ran out of samples inside a burst (SC-25) |
  | `radio.TX_DISCONTINUITY` | warning | mark_artifact | the burst tracker reported a discontinuity (SC-24a) |
  | `radio.TIME_ERROR` | error | mark_artifact | a burst's target was too close or past (RM-14), or the device model saw an unclosed burst followed by a timed block (spec 02 decision S12) |
  | `radio.LATE_COMMAND` | warning | mark_artifact | a timed command or a stream start arrived with too little lead (UC-6, MR-11) |
  | `radio.ALIGNMENT_ERROR` | error | mark_artifact | channels of one stream lost alignment (SC-13, SC-31) |
  | `radio.CLOCK_LOST` | fatal | abort | the device lost its reference |
  | `radio.COMMAND_QUEUE_FULL` | error | abort | a timed command found the device's queue full (UC-6) |
  | `radio.COMMAND_REJECTED` | error | mark_artifact | the Provider could not carry out an admitted Action: an unsupported Action, a malformed waveform, a target it does not have, a configuration its envelope refuses |

  MockRadio never emits `radio.TX_UNDERFLOW`, `radio.TX_DISCONTINUITY`, `radio.ALIGNMENT_ERROR` or `radio.CLOCK_LOST`; the UHD Provider emits all but `radio.TX_DISCONTINUITY` (spec 18 UR-19, UR-27, UR-28).
  *Test:* `rm_10_the_kinds_are_registered_under_radio_with_their_defaults`; none named for MockRadio's four never-emitted kinds and for the UHD Provider's never emitting `radio.TX_DISCONTINUITY`.
- **RM-11** Every radio event is emitted with `emit_control`, except `radio.RX_OVERFLOW`, which every radio Provider must emit on the hot path (`EventSink::emit`, RS-32) with RM-24's bytes. The source node is the stream's own `<device>/rx/s<k>` or `<device>/tx/s<k>` node (RM-3) for `radio.RX_OVERFLOW`, `radio.ALIGNMENT_ERROR`, `radio.TX_UNDERFLOW` and `radio.TIME_ERROR`; the device node for `radio.COMMAND_QUEUE_FULL`, `radio.COMMAND_REJECTED` and `radio.CLOCK_LOST`; and for `radio.LATE_COMMAND` the device node when it answers a `hardware_timed` update, a `cold` change or a start, and the receive stream's node when it reports that stream's missed timed start (spec 18 UR-17). No Provider has a transmit port fed by a link yet, so none emits `radio.TX_DISCONTINUITY`; SC-24a's Producer obligation is the first such Provider. `time` is in the stream's SampleClock or, before one exists, the Authority's primary root, and the payload is, on the control path, a JSON object with exactly these members:

  | Kind | Payload |
  |---|---|
  | `radio.RX_OVERFLOW` | `{ "cause": "overrun" \| "sequence", "lost": int }`; on the hot path, RM-24's bytes |
  | `radio.TIME_ERROR` | `{ "cause": "late" \| "unclosed_burst", "outcome": "send_asap" \| "drop" \| "plan_violation" \| "refused" \| "late_at_device", "late_by_ns": int, "target": TimePoint }` |
  | `radio.LATE_COMMAND` | `{ "key": string \| null, "requested": TimePoint, "applied": TimePoint }` |
  | `radio.COMMAND_QUEUE_FULL` | `{ "key": string, "depth": int }` |
  | `radio.COMMAND_REJECTED` | `{ "action"?: ActionId, "kind": string, "reason": string }` (`kind` is the Action's `kind` tag; `action` is the id it was dispatched with (`Dispatched.id`, MA-14) when the Provider refuses it on receipt, and is absent when something it booked earlier is refused as it applies, when that id is no longer at hand) |
  | `radio.TX_UNDERFLOW` | `{ "cause": "starved" \| "lost" }`: `starved`, the device ran out of samples inside a burst because the host was late; `lost`, samples of a burst were lost between host and device |
  | `radio.ALIGNMENT_ERROR` | `{ "lost": int }`: the samples, on every channel of the stream, that the misalignment removed, which is the next block's time jump |
  | `radio.CLOCK_LOST` | `{ "reference": "frequency" }`: the frequency reference (10 MHz) was lost; no Provider monitors its time reference (PPS), so no other value is declared |

  `TIME_ERROR`'s outcome `late_at_device` means that the Provider handed the burst to the device in time by its own clock and the device reported that it arrived too late, so nothing was transmitted; `late_by_ns` is the device's reported instant less the target when the device reports one, and 0 otherwise.

  Each payload is the JSON serialisation of the RM-22 type of its kind, never a hand-built object.
  *Producer obligation.*
  *Test:* `rm_22_payloads_round_trip`, `mr_29_other_actions_are_command_rejected`, `mr_10_events_carry_the_source_the_context_gave`, `mr_16_burst_refusals`, `mr_37_the_overflow_travels_the_hot_path`, `mr_11_start_cases`, `mr_18_hardware_timed_updates`, `ur_19_reports_before_one_block_keep_each_kind`, `mr_28_a_layout_instance_s_events_name_their_stream_node`, `ur_27_a_lost_reference_is_clock_lost` (the device node as `CLOCK_LOST`'s source) and `ur_28_a_layout_transmit_report_names_its_stream` (the stream node as `TX_UNDERFLOW`'s); none named for the receive stream's node as the source of `LATE_COMMAND` on a missed timed start.

### Verbs and bursts

- **RM-12** The Session verbs are: `start_repeat` → `CompileRule::TxBurst { repeat: true, late_policy: send_asap_and_flag }`; `send` → `CompileRule::TxBurst { repeat: false, late_policy: drop_and_flag }`. Their target is the transmit stream node `<resource>/tx/s<k>` (RM-13). `start_rx` → `CompileRule::Command {}`: its target is the receive stream node `<resource>/rx/s<k>`, it carries no params, and it turns the stream on again after a `Stop` as RM-21 says; its `at` is the instant at or after which it takes effect, never late. A stream's node may also be the target of an `UpdateParameter` and of a `Stop` (RM-13, RM-16): `ezsdr_radio::stream_target` reads `"<device>/rx/s<k>"` and `"<device>/tx/s<k>"` — `k` in SB-2a's spelling, without a leading zero — and no other id, the changed key decides what changes, and the node only selects the SpecTime clock the schedule's item is on (SB-16).
  *Test:* `rm_12_the_verbs_compile_as_declared` (the verb names, the `CompileRule`s and the registration); `mr_29_start_rx_is_the_one_command` (the target, the empty params and the restart after a `Stop`); `mr_29_start_rx_takes_effect_at_its_at`, `mr_29_a_receive_link_never_begins_before_t0` and `mr_29_start_rx_is_never_late` (the `at`, the T0 floor a receive link keeps, and the never-late instant); `rm_12_a_stream_node_names_its_direction_and_number` (which ids name a stream).
- **RM-13** A `TxBurst` targets `<device>/tx/s<k>` and its `ArtifactRef` holds complex samples in that stream's `ezsdr.stream.cf32` contract, channel-interleaved (sample `n` of channel `c` at byte offset `(n · channels + c) · 8`), little-endian; `channels` is the number of channels the stream holds and channel `i` is that set's `i`-th smallest logical channel (RM-3, RM-30). Its length is `size_bytes / (8 · channels)`, a whole number ≥ 1. The burst transmits on every channel of the stream. A repeated waveform's length must be at most `radio.tx.repeat_max_samples` and a multiple of `radio.tx.repeat_align_samples`. `TxBurst.metadata` is unused and must be empty. A start equal to a held burst's is refused by RM-15.
  A radio Provider refuses a `TxBurst` with `radio.COMMAND_REJECTED`, and transmits nothing, when:
  - its target is not the transmit stream node;
  - the transmit stream holds no channel (RM-21);
  - `size_bytes` is not a positive multiple of `8 · channels`;
  - a sample component is not finite, where the Provider reads the waveform's bytes;
  - it repeats and its length is above `radio.tx.repeat_max_samples` or not a multiple of `radio.tx.repeat_align_samples`;
  - `metadata` is not empty; or
  - its start is before the Provider's synchronisation end (the instant MR-9 and UR-13 state).

  A burst whose waveform does not have the contract, the channel interleaving or the byte order above is not transmitted and is reported with `radio.COMMAND_REJECTED`.
  *Producer obligation.*
  *Test:* `mr_16_burst_refusals`, `mr_32_waveform_refusals`, `ur_21_txburst_refusals` and `rm_12_a_stream_node_names_its_direction_and_number`; the channel interleaving and the little-endian byte order by `mr_32_a_two_channel_waveform_is_channel_interleaved`; none named for a waveform refused for not having the `ezsdr.stream.cf32` contract.
- **RM-14** On receipt of a `TxBurst` a radio Provider evaluates `LatePolicy::decide(registry, at, now, device_lead)`, where `device_lead` is its **device lead** — its TimingEnvelope's `radio.timing.min_timed_command_lead_ns` less the delivery allowance it declares (MA-10), in `host.monotonic` (SC-27) — and `now` is its **decision instant**: the first transmit sample at or after the later of its current instant and its transmit clock's origin less that device lead, so that a target whose instant has passed is late even when it is the sample the current instant falls in, and a burst timed before the origin of the clock a `cold` transmit change or an enable starts is late (RM-15). A stepped Provider's allowance is zero, so for MockRadio the device lead is the TimingEnvelope's lead. `OnTime`: the burst starts at `at`. `SendAsap`: the target moves to the first transmit sample at or after the decision instant plus the device lead; if admitted, `radio.TIME_ERROR { cause: late, outcome: send_asap }` is emitted.
  Under `SendAsap`, `BurstOpen.requested_target` is the burst's original `at`, or SC-23a's `requested_at` when admission already advanced it. If its Provider refuses that moved start, the burst is not transmitted and the Provider emits only `TIME_ERROR { outcome: refused }` plus `COMMAND_REJECTED` instead of a `send_asap` event. `Drop` and `PlanViolation`: the burst is not transmitted, and `radio.TIME_ERROR` with that outcome is emitted. The outcome reaches an admitted burst's `BurstRecord` through `BurstOpen.late` (SC-29a).
  *Producer obligation.*
  *Test:* `mr_17_a_target_whose_instant_has_passed_is_late_even_on_the_floor_sample`, `mr_17_a_burst_before_its_clock_s_origin_is_late`, `ur_21_a_burst_before_its_clock_s_origin_is_late`, `mr_16_burst_refusals`, `ur_21_first_dispatch_rechecks_all_late_policies`, `v58_09_a_pong_short_of_the_lead_is_late_as_on_hardware`, `rm_14_the_recorded_requested_target_is_the_requested_at` and `rm_14_the_handed_burst_keeps_its_requested_at` (SC-23a's `requested_at` kept as `requested_target` on time and after a `SendAsap` move, MockRadio and the UHD Module).
- **RM-15** Bursts on one transmit stream are held in target order. A burst ends at the end of its waveform (without `repeat`), at the start of the next burst, at a `Stop` for its stream or device, at a `cold` change of the stream (UC-3), or at the Run's stop, whichever is first; a repeated burst ends only at one of the last four. A burst whose start equals a burst already held — the start its Provider's `LatePolicy` decided (RM-14) — is refused with `radio.COMMAND_REJECTED`. Every block a Provider transmits goes through the Kernel's `BurstTracker` (SC-29).
  A burst never starts before its transmit clock's origin: a target before it is late, and the burst's `LatePolicy` applies — `send_asap` moves it to the origin with `TIME_ERROR { send_asap }`, `drop` drops it. A burst timed before the origin of the clock a `cold` transmit change or an enable starts meets this on a Provider whose start lead is not zero (a Session burst with no `at` does not: RS-19 admits it no earlier than that origin); its Provider decides such a burst as if at its clock's origin less its device lead.
  A Provider that hands a burst's samples to a device ahead of their instants, and cannot recall them, cannot start the next burst before the first sample it has not yet handed over. For a burst that would start while another is open, the Provider decides it again when it takes it to transmit, against that first unhanded sample — which only the part of the Provider that hands samples over advances, so the decision and the hand-over cannot race —, and a target before it is late, with the burst's `LatePolicy` applied as above; the open burst ends at the next burst's start as decided.
  The Provider's spec states the in-flight window, the most it hands over ahead of the device's time. MockRadio hands nothing over ahead, so its bounds are `now + device_lead` and the origin, which waits its profile's start lead.
  *Producer obligation.*
- **RM-16** A receive segment ends at its **cut**: the first sample at or after the instant of what ends it — a `Stop` of `<device>/rx/s<k>` or `<device>`, `Provider::stop`, a device loss or a `cold` change (RM-21) — and never before its origin or the first sample not yet delivered; under `abort`, the first sample not yet delivered. Nothing at or after the cut is delivered. A `Stop` takes effect at the instant the Provider handles it.
  On the transmit side a `Stop` of `<device>/tx/s<k>` or `<device>`, and `Provider::stop`, close the open burst at the first sample at or after the instant (`BurstEnd::Stop`), every earlier sample transmitted, and cancel the held bursts starting at or after it; a later burst is transmitted as usual (RM-15). A Provider that hands samples ahead ends a stopped burst at the last sample handed over, within its in-flight window. A `Stop` cancels no update. `Provider::stop` and a device loss settle every command the device was not given by the Run's end instant `S` at `S`, and record the given ones whose instant came: one due by `S` (a loss: before `S`) keeps the result it would have had — issued, or `no channel` when no channel was in force — and one due after `S` is cancelled, whether a device was handed it or not. A stop settles a command due at `S` first and a loss itself first (RM-21).
  A command is **handed over by `S`** when the device's time read just before its device call began — with several channels, the last channel's `apply` — is at or before `S` for a stop and before `S` for a loss; a call that straddles `S` counts at its start, since a device returns no acceptance instant. One due by `S` that no release handed to the device by `S` is the **Ceiling**: the Module's own release delay — its poll, a synchronous device call while booking, a channel-less command at the head, a loss just before the apply — left a live command unsettled, and it is cancelled like one due after `S`; `no channel` is for a command whose instant passed with no channel to give it on.
  A held `TxBurst` cancelled before its start by `Stop`, `Provider::stop`, loss or a `cold` change is recorded in the Provider's `rejected` section; only a `cold` change emits `radio.COMMAND_REJECTED`.
  *Producer obligation.*

### Receive faults

- **RM-17** An **overrun** at `f` loses every receive sample in `[f, f + radio.timing.overflow_restart_gap_ns)`. The block in progress ends at `k_f`, the first sample at or after `f`, and is delivered if it holds a sample. The next block begins at the first sample at or after `f + gap`; if a sample was lost it carries `GAP_BEFORE | RESTARTED` and `lost` equal to its whole time jump, any loss already pending included (SC-18). For a block with a jump, the reports since the preceding block produce at most one `radio.RX_OVERFLOW`, with `lost` the block's whole jump less any loss an earlier event already reported (the dropped-block overrun below), `cause: overrun` if any report was an overrun and otherwise `cause: sequence`, timed at the first sample of that loss in the receive `SampleClock`. A block without a jump consumes its pending reports without an event; a report with no following block produces no event. A jump with no report produces no event. An overrun the Provider causes by dropping a block its link refused is emitted when it drops it, outside this rule (SC-20a).

### The lattice

- **RM-25** Every SampleClock's origin is on its root's lattice — a whole multiple of the numerator, in lowest terms, of its `root_ticks_per_tick` — so clocks of one ratio share every sample instant and T0 is a sample instant of every stream. The first receive segment starts at T0 (MR-11, UR-15), the first transmit clock at the first lattice instant at or after `arm` (MR-9). A receive segment whose device misses its timed start keeps its origin: its first block carries `GAP_BEFORE` with `lost` its index (SC-13), so an index still names `origin + index · root_ticks_per_tick`. Every later one starts at the first lattice instant at or after its effective instant, the stream's previous cut plus its own direction's `radio.timing.{rx,tx}_start_lead_ns`, the instant the Provider is ready for it plus that lead, and, for an item RM-34 gives a release, that release plus the lead; the Provider's spec states its ready instant, and a Mock profile emulating a device states that device's.
  Commands and faults of one stream take effect in the order of their effective instants and, at one instant, in the order received, faults — a device loss among them — counting as received at the Run's start; `Provider::stop` is a command and counts in the order it was received. A `cold` change never takes effect before an earlier `cold` change of its stream: its effective instant is floored at that change's, the two keep their order of arrival, and it is applied late as UC-2 says (`LATE_COMMAND`). With a layout description (RM-29), a Provider floors an `UpdateParameter` of a `cold` key at every earlier, still-pending `cold` change of the same instance, whatever direction, stream or line it belongs to; a change canceled by `Provider::stop` or device loss does not floor a later one. It computes that floor with `ezsdr_radio::timeline::layout_instant(at, now, start, earlier)` — `earlier` the effective instants of its instance's still-pending `cold` changes and `start` a receive stream's start —; both Providers call it. It also floors a change whose key belongs to a receive stream at that stream's start (RM-21), and reports `LATE_COMMAND` when the effective instant is later than the requested instant, including when that start is the floor. Between a cut and the next origin nothing is delivered and nothing is a gap.
 A stream's configuration is the set of channels it holds and its rate (RM-21), so a `cold` change to another set of the same size is another configuration and begins a new segment, and a stream whose set is empty begins none.
  A receive SampleClock is registered with the first block its segment publishes and ended at its cut, so a segment that publishes none — one cut at or before its origin, or one whose samples were all lost before a loss or an abort — has none; a transmit clock is registered, and its predecessor ended, when its change is booked, so that a burst admitted after it can target it (KC-21a).
  A planned event refused or pre-empted at its instant — a configuration the device does not apply, a loss, `Provider::stop` — is removed; cuts made and clocks ended stand, and only the events after that instant are recomputed, a later one the new plan refuses being refused then (`COMMAND_REJECTED`). A refused change or start — a `cold` change, an enable or a `start_rx` whose configuration the device does not apply — **halts** the stream: it has no segment until the next `cold` change or `start_rx`, which starts it by the rule above; the refused value stays the configuration of record (KC-27), which that change or `start_rx` starts from, and a halted stream has no channel for a `hardware_timed` update, whose value is recorded and applies when the stream starts again; a transmit clock registered for the refused change ends at its origin — or at the cut a change booked earlier has already made of it —, its held bursts cancelled (`COMMAND_REJECTED`). Only transmit clocks can so end with no sample. MockRadio raises this refusal through spec 08's `cold_change_refused` fault, choosing the change it refuses as spec 09 MR-20 says.
  Both Providers use `ezsdr_radio::timeline` for stream planning; a layout instance's lines, moves and instance-wide floor use `timeline::Lines` and `timeline::layout_instant`.
  A line may prune items before a boundary only when no later booking can take effect before it and no later refusal can reach a pruned item. It folds pruned items into its starting state, and pruning leaves the line's plan unchanged.
  *Producer obligation.*
  *Test:* `rm_26_the_timeline_cases`, `rm_26_each_stream_takes_its_own_directions_start_lead`, `rm_26_a_line_pruned_at_an_item_s_instant_keeps_it`, `rm_26_a_pruned_line_keeps_few_items`, `rm_26_a_pruned_line_plans_as_one_that_keeps_every_item`, `rm_26_a_refused_booking_leaves_the_line`, `rm_26_pruning_folds_a_cold_change_floored_at_an_earlier_one`, `rm_26_generated_sequences_keep_the_timeline_invariants`, `rm_21_a_cold_change_to_another_set_of_the_same_size_starts_a_segment`, `rm_21_a_stream_that_loses_its_last_channel_starts_again_when_one_enters`, `mr_18_a_cold_change_starts_its_clock_on_the_lattice`, `ur_15_every_clock_starts_on_its_lattice`, `ur_17_a_missed_start_restarts_with_a_gap`, `rm_26_the_timeline_against_uhd_rx`, `mr_18_a_layout_cold_change_is_floored_at_every_earlier_cold_change`, `mr_18_a_layout_cold_floor_crosses_directions`, `mr_18_a_layout_reservations_cannot_invalidate_an_earlier_one`, `mr_18_a_layout_cold_floor_holds_without_a_line`, `mr_18_a_layout_receive_floor_at_t0_emits_late_command`, `rm_25_the_layout_instant_is_floored_at_every_earlier_cold_change` and `ur_25_a_layout_cold_change_is_floored_at_every_earlier_cold_change_of_the_instance`;

- **RM-34** One logical channel moves from the stream that holds it to another stream of the same instance in one operation of `ezsdr_radio::timeline`, never by changing one stream's configuration alone.   `refuse_move` refuses both lines' item of that `seq`, which each line keeps as its configuration of record, and replans both: they halt until their next successful `cold` change or `start_rx` (RM-25), and a `seq` that names no move is no move. `Lines::refuse(stream, seq)` refuses a move's `seq` on both lines the same way, whichever of them it names. ## 7. Vision issues found

1. **Resolved:** Vision §8's example uses per-channel membership and phase-behavior keys and per-stream rate keys (RM-27).
2. **Resolved:** Vision §13 says the Radio Model Vocabulary defines coercion rules and that supported stream-rate grids are declared as capabilities, not as an envelope member (RM-8).
3. **Resolved:** Vision §22 now says `TxBurst.format` is determined by the transmit stream's Stream Contract and that the burst uses every channel of that stream (RM-13).
4. **Resolved:** Vision §26 says phase behavior is declared per logical channel and MockRadio emulates it (RM-9, MR-34).

## 8. Deferred

A transmit port and link-fed transmission (Phase 10). DDC/DUC and decimation capabilities, device FFT (spec 18's Not in scope). A per-Run delay override by a CalibrationArtifact (Vision §26). A BasicRX/BasicTX tuning upper bound is the DDC's range, `master_clock_hz / 2`; UHD's overall range reaches 350 MHz at 200 MHz, which the DDC's ±100 MHz does not confirm (INFERRED; a bench measurement decides). An LFRX/LFTX tunes within 0…32 MHz, the board's own range; UHD's overall range is wider (0…64 MHz for the two-input modes), so this bound can refuse a tuning the device may accept (INFERRED; the board's range is what the bench confirms). Basic/LF phase behaviour `random_unless_timed_tune` stands in for the inferred `deterministic` until a timed-tune measurement confirms the stronger value (INFERRED).
