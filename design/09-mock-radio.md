## 1. Purpose

Vision §12: "Mock is a peer *because* it implements the same contract **and the same constraint envelope**. A Mock that accepts what its emulated hardware would reject is a bug." This document specifies a MockRadio that implements spec 07 exactly, enforces the `x3xx` envelope, and produces the same flags, gaps, events and records a USRP would, so that the parity test has something precise to compare against.

## 2. Evidence

The values of MR-3 come from these sources, each marked in the table:

- **VERIFIED** (audit Appendix B, UHD documentation): X310 master clock 200 MHz with integer decimation; two RX and two TX channels per motherboard; `OVERRUN_RESTART_DELAY = 0.05 s`; `set_time_unknown_pps` takes up to two seconds; about 2 000 `sc16` samples per 10 GbE packet; UBX-160 daughterboards tune 10 MHz–6 GHz with gain 0–31.5 dB in 0.5 dB steps; random inter-frontend phase after an untimed retune.
- **INFERRED** (engineering judgement where UHD states no number; Y13 takes the stricter value): the 2 ms minimum timed-command lead, the command-queue depth of 16, the 1.0 GB/s per-direction transport of one 10 GbE link (its 1.25 GB/s line rate less framing, rounded down), Replay's 2-sample alignment and 256 Mi-sample maximum. Phase 8 measures each (Vision §59); versions follow AGENTS.md §6.

### Identity and construction

### `coerce`

- **MR-6** `coerce(request)` is pure (MA-11) and is the layout description's `coerce(…)` (RM-30), which computes:
  1. `request.resource` must be the device node; otherwise `Err(Rejected)`.
  2. For each constraint on a **capability** key: applied is the declared value when it satisfies the constraint (`binding::satisfies`), and the key is `rejected` otherwise. A key outside RM-4 is `rejected` with reason `"RM-4: not a radio key"`.
  3. For each constraint on a **configuration** key: RM-8's rule over MR-3's grid, where an `Int` is read as the number it is. For `ideal`, a non-integer sample rate is `rejected` ("RM-8: this device represents a rate as whole hertz", TM-20). An `Eq` value off the grid gives a `Coercion` with reason `"RM-8: nearest grid value"`.
  4. RM-32's PerformanceEnvelope judgement over the resulting configuration, MR-5's defaults included; a violation removes the named key from `applied` and adds a `rejected` entry with reason `"RM-32: <d> needs <x> B/s, one link carries <y>"`.
  5. `applied` holds exactly the requested keys that were not rejected; `warnings` is empty.
  A channel or stream number absent from the layout is refused as `RM-4: no such channel c<n>` or `RM-4: no such stream s<k>`.
  *Test:* `mr_06_coerce_cases` (20.25 → 20.0, 7 GHz rejected, `Min(1.1e6)` → 200e6/181, two channels at 200 Msps rejected, `ideal` at 19.5e6 accepted and at 1e6/3 rejected, `antenna: J1` rejected, and absent `c2` refused), `mr_06_coerce_is_pure` and `mr_07_prepare_reports_the_coercions_coerce_reported`; none named for a `Requested` whose `resource` is not the device node.
### `prepare`, `arm`, `start`

- **MR-7** `prepare(fragment, ctx)`:
  1. A second `prepare` on one instance returns `Rejected` ("MR-7: prepare was already called", MA-7).
  2. `ctx.class` other than Simulation returns `Unsupported` (KC-2).
  3. `fragment.content.requested` must parse as a `Requested` naming the device node; its `coerce` report must have no `rejected` entry; otherwise `Rejected`.
  4. The configuration is MR-5's defaults overlaid with the report's `applied` configuration keys.
  5. The primary root `V = ctx.time.primary_root()` must have an integer nominal rate `R` (`ctx.clocks.nominal_rate(V)`, denominator 1); otherwise `Unsupported`.
  6. For each receive and each transmit stream whose set of channels is not empty, declare its SampleClock: `ctx.clocks.declare_sample_clock(<that stream's node>, V, ratio)` with `ratio = R · N / 200 000 000` for `x3xx` at decimation `N` (one of the DDC's; design 33 D5), and `R / rate` for `ideal`, as a reduced `Rational` computed from integers, never from the `f64` rate (TM-20). Stream `<device>/d/s<k>` holds the channels whose `radio.d.c<n>.stream` is `k`, and its rate is `radio.d.s<k>.sample_rate_hz` (RM-27, RM-29, RM-30).
  7. Every `ctx.links` entry must be `{ component: fragment.id, port: <one of this instance's receive ports>, StreamOut }`; receive stream `k` uses `rx<k>` (RM-29). Any other entry is `Rejected`. Among one port's links, one whose `policy()` is `Block` must be that port's only link (the refusal reads "MR-7: multiple rx links cannot use Block back-pressure", one port's rule).
  8. The fault entries of `ezsdr_sim::faults(&ctx.environment)` whose `target` is `fragment.id` are kept (SE-4); a reader error is `Rejected`. The jitter generator of a receive stream is `SimRng::new(ezsdr_sim::seed(&ctx.environment)?, <that stream's node>)` (MR-12).
  9. The handles of `ctx` are kept (MA-5a).
  10. It returns `PrepareReport { effective: <RM-30's configuration keys>, coercions: the report's, warnings: [] }`.

  `prepare` does not block (MA-8).
  *Test:* `mr_07_prepare_cases`, `mr_07_prepare_reports_the_coercions_coerce_reported`, `v58_11_19_5_msps_is_coerced_to_20`, `mr_39_each_receive_stream_declares_and_runs_its_own_clock`, `mr_38_the_tree_and_capabilities_are_the_layout_s` and `mr_7_each_receive_port_takes_its_own_links`; none named for step 10's empty `warnings`.
- **MR-8** The coercions `prepare` reports are those `coerce` returned for the fragment's `requested` (MA-12, SB-44).
  *Test:* `mr_07_prepare_reports_the_coercions_coerce_reported`.
- **MR-9** `arm()` records the arm instant `A = now(V)` and the synchronisation end `S = A + startup_latency_ns` (rescaled to `V`, rounded up). For each transmit stream whose set of channels is not empty, it registers that stream's transmit SampleClock with origin the first instant at or after `A` on the root's lattice (TM-13e; RM-25), and it books every transmit stream's line, that stream's own configuration (RM-25, RM-29).
  *Test:* `mr_09_the_transmit_clock_starts_on_its_lattice`; two layout streams' own clocks, lines, held bursts and rate change by `mr_09_each_transmit_stream_has_its_own_clock_and_line`.
- **MR-10** Stream ids are `<device>/rx/s<k>` and `<device>/tx/s<k>` (RM-29), and every SampleClock the Mock declares or registers uses its own stream's id. A `cold` change declares a new clock for the same stream (UC-3).
  *Test:* `mr_11_start_cases`, `mr_02_the_tree_has_the_radio_model_shape` and `mr_39_each_receive_stream_declares_and_runs_its_own_clock`.
- **MR-11** `start(at)` takes `T0 = at` (the coordinator always passes `Some`; `None` is taken as `now(V)`). If `T0 < S`, it emits `radio.LATE_COMMAND { key: null, requested: T0, applied: S }` and returns `Rejected` with the reason `"MR-11: the start at <T0> precedes synchronisation at <S>; the profile needs ezsdr.time.start_lead_ns ≥ <startup_latency_ns>"`, and no stream starts. Otherwise every receive stream with a link is booked on its line, and each whose set of channels is not empty begins its first segment at `T0`, its SampleClock registered with origin `T0` with its first block (RM-25), so its first sample is tick 0 at T0 (TM-13b); it then inserts each kept fault as a pending event at `T0 + at_ns` and schedules its wakeup as MR-14 says. A start that fails leaves no receive stream begun and every transmit stream's line booked at `arm` (RM-25).
  *Test:* `mr_11_start_cases` (the refusal's reason, and its `LATE_COMMAND` source and time; none named for that payload's `key`, `requested` and `applied`, for the refused start leaving no stream started, or for `None` taken as `now(V)`); the layout streams' first segments by `mr_39_each_receive_stream_declares_and_runs_its_own_clock`.

### Receive

- **MR-12** A receive block's length is `radio.rx.block_len` (2 000). With `block_len_jitter`, each block's length is instead `1 + rng.below(2 · block_len)`, drawn when the block begins, in block order, from its own stream's generator. A block is shortened to end at the next fault, `cold` change or stream end. Consecutive blocks are contiguous except across an injected gap.
  *Test:* `mr_12_block_lengths` (without jitter every length is 2 000; with it every length is in 1…4 000, differs from another seed's and is contiguous with the next block's), `mr_12_jitter_draws_belong_to_blocks_after_a_receive_cut` (the draw `1 + rng.below(2 · block_len)` in block order and the shortening at a fault), the shortening at a `cold` change by `mr_18_a_fractional_receive_cut_is_the_first_sample_at_or_after_e` (the old stream's samples all delivered up to the cut) and at the stream end by `mr_25_a_stop_cuts_at_its_instant` (the last block ending at the cut, for a `Stop` of the stream, of the device and `stop`); each layout stream's own generator by `mr_30_two_layout_mocks_one_seed_identical_output`.
- **MR-13** Receive samples are `ezsdr.stream.cf32` in SC-4's planar layout. In channel mode (MR-31) the samples are MR-35's and the pattern is `zero`. With `rx_test_pattern: zero` every byte is 0, written explicitly. With `ramp`, sample index `k` (the block's SampleClock tick) of channel `c` is `re = (k mod 65 536) / 65 536`, `im = c / 64`, as `f32`, little-endian; `c` is the channel's position in the block, the `i`-th smallest logical channel of the stream's set (RM-3). Each block's bytes come from a `HostPool` (HD-2) and the block is built with `SampleBlock::new_host(header, HOST_MEMORY, bytes, 8)` (SC-8), with `valid` full, `direction: rx`, and flags only as MR-21 and MR-22 set them.
  *Test:* `mr_13_ramp_values` (the bytes, the planar offsets and the memory domain; the flags of a receive block are asserted by `mr_19_backpressure_is_an_overrun`, `mr_20_a_fault_between_cold_clocks_is_not_applied` and `mr_29_start_rx_is_the_one_command`); a receive block's `valid` full by `test_v57_repeat_then_capture_in_software` (a 3 000-sample capture whose continuity `valid` is one stretch, so no block in it carried an invalid sample); none named for a block's `direction: rx`; the layout block's channels and the position `c` by `mr_13_a_stream_s_block_channels_follow_its_channel_set`.
- **MR-14** A receive block is published once its last sample is in the past: in `step(until)`, a block `[s, s + L)` is published when `until` is strictly after the instant of sample `s + L − 1`, that is at or after that instant's floor plus one root tick. A sample is never delivered at the instant it is taken, and a block computed from the SimulationChannel is then final whatever order the stepping loop steps the Mocks in (spec 11 CH-9). It is published to every attached receive-stream link, the same `BlockRef` to each (SC-11, SC-22). After publishing what is due, the Mock schedules a wakeup at the earliest of: the first root tick strictly after the next receive block's last sample, the first root tick strictly after the next transmit block's last sample, and the earliest pending event (a fault, a command, a burst start, the stream end). It holds **at most one** scheduled wakeup: one at another instant is cancelled first, one at the same instant is kept.
  *Test:* `mr_14_blocks_appear_when_their_last_sample_has_occurred`, `mr_14_a_block_is_published_strictly_after_its_last_sample` and `ch_09_the_receive_output_does_not_depend_on_the_stepping_order`; none named for a Mock with more than one `rx` link receiving the same `BlockRef`.

### Transmit

- **MR-15** Transmit blocks are headers only, fed to the Kernel's `BurstTracker` and to the device model (MR-24); their bytes are never built. `BurstTracker::new(tx domain)` and `DeviceModel::new()` are created whenever a transmit SampleClock is registered — at `arm` and at a `cold` transmit change (MR-18) — replacing the ones of the ended clock, after `BurstTracker::stop` closed its burst. A transmit block has length `radio.rx.block_len`, shortened at the waveform's end, at a wrap of a repeated waveform, at the next burst's start, at a `cold` transmit change and at the transmit stream's end; a block that ends at the next burst's start carries `END_OF_BURST`; the first block of a burst carries `START_OF_BURST` and a `BurstOpen { waveform_len: Some(L), late, requested_target }`, and the last `END_OF_BURST`, except when the burst ends by `stop` or a `cold` change, which closes it with `BurstTracker::stop`.
  The Mock has no device feedback and never calls `BurstTracker::set_actual_start`, so `BurstRecord.actual_start` is absent (SC-28: "where the Provider can supply it"). A block is emitted once its last sample is in the past, as MR-14 says of a receive block: when `until` is strictly after the instant of its last sample. An Action handled at the instant of a transmit sample, in whichever pass of that round, therefore finds that sample not yet transmitted, and a stop's cut (MR-25), MR-16's refusals and the burst records agree with what is radiated.
  *Test:* `mr_15_a_transmit_block_is_emitted_only_after_its_last_sample`; none named for `BurstRecord.actual_start` being absent.
- **MR-16** A `TxBurst` is refused with `radio.COMMAND_REJECTED` when:
  - it breaks one of the refusals RM-13 states for every radio Provider;
  - its `at` is not on the current transmit SampleClock or on one a booked `cold` change registered (KC-21a, RM-25), where it is held until that clock is current. MockRadio takes the transmit clock whose domain is `at`'s, not older than the current one, and either the current one or a booked one whose plan segment is not yet cut or is cut only at a sample above 0, so an `at` on the previous clock is still accepted after a booking, whose clock becomes current only when the change applies; or
  - it would start at or before the open burst's next sample.

  Its target is the transmit stream's own node (RM-13, RM-29), and the channel count it is judged against is that stream's set of channels (RM-3, RM-30), selected by `radio.tx.c<n>.stream`. In channel mode MR-32's three waveform refusals follow the repeat constraints and precede MR-17's decision. Otherwise the burst is decided by MR-17 and held (RM-15). A repeated burst is transmitted so that repetition `w` begins at `target + w · L` and the block sequence is contiguous across every wrap (SC-26); it never underflows.
  *Test:* `mr_16_burst_refusals`, `mr_16_a_burst_at_or_before_the_open_burst_s_next_sample_is_refused` and `mr_16_repeat_is_contiguous_across_wraps` (a waveform of 1 000 samples repeated over 5 000: the record's `blocks`, `samples`, `wraps` and `end` are 5, 5 000, 5 and `Stop` — `wraps` counts complete repetitions, and no test reads each block's length or each wrap's `Continued`; and, against a `BurstTracker` driven directly, the v3 tail pattern 300, 300, 300, 100, 300 with `Started` on its first block and `Continued` on the four after it, none a `Discontinuity`, which `sc_26_burst_repeat_wrap_contiguous` asserts of the same four); the layout's target by `mr_12_d14_the_actions_of_a_layout_instance_name_a_stream`, each layout stream's own channel count by `mr_16_each_transmit_stream_is_judged_by_its_own_channel_count`, and a burst on a booked clock whose segment is not yet cut by `mr_18_a_burst_on_a_later_clock_survives_an_earlier_switch`; none named for a booked clock cut only at a sample above 0 or for an `at` on the old clock after a booking.
- **MR-17** On receipt at `now`, the Mock decides a `TxBurst` against the later of RM-14's ordinary start bound and its transmit stream's conservative in-flight front on the same SampleClock. At horizon `now + W`, an earlier-received burst contributes only when its start is before the first sample at or after the horizon; its contribution is the earlier of its exclusive end and the horizon, or the horizon for a repeat. Receipt order includes earlier Actions at the same instant. When `tx_in_flight_ns` is nonzero, the reservation frontier is two samples after the handed payload end, including when a burst closes or Stop occurs; zero adds no frontier. A Mock's two-sample bound may be later than a Provider's actual hand-over cursor; equality is on time at each Module's own bound. `LatePolicy` and `late_by` are applied at that bound, and `TIME_ERROR` stays floored at `now` in the transmit SampleClock (RM-11).

## 4. The step algorithm

`step(until)` is MR-12…MR-25 in one order, so that commands, faults and block boundaries interleave exactly:

```text
step(until):
  if device_lost has fired and was reported: refuse every Action received (MR-20); return { progressed: false }
  now := time.now(V)                                   -- equals `until` in the Simulation class
  for each Action in actions.recv() order: handle it at `now`   (MR-16, MR-17, MR-18, MR-25's Stop, MR-29)
      — or, when a device_lost fault not yet applied has its instant ≤ until, refuse it: record it in
      `rejected` with "MR-20: device lost" (MR-20)
      -- a transmit Stop first emits the block in progress up to its first sample at or after `now` (MR-25)
  progressed := any Action handled
  loop:
      emit every receive block whose last sample is before until (MR-14) and that ends at or before the first sample at or
          after the earliest pending RECEIVE CUT — an rx_overflow, rx_sequence_error or device_lost fault, or the
          segment's cut in the timeline's plan (RM-16, RM-25) — shortening the block in progress to end there
      emit every transmit block whose last sample is before until (MR-15) and that ends at or before the earliest pending
          TRANSMIT CUT — the next held burst's start, a cold transmit change, the transmit stream's end — and
          at its burst's waveform end or wrap (MR-15)
      E := the earliest pending event of any kind (a receive segment's origin, first at its instant; a fault, a
          command, a burst start)
      if E is none or E's instant > until: break
      apply E (ties in (instant, insertion) order): a command (MR-18), a fault (MR-20…MR-22, recorded as it fires),
          a receive segment beginning (RM-25), a burst start (MR-15), an untimed tune (MR-34) after the others at its instant — a `device_lost` fault stops the device at its instant
          and ends the step: return Err(DeviceLost) (MR-20)
      progressed := true
  schedule the wakeup of MR-14
  progressed |= any block emitted
  return { progressed }
```

"Emit" includes the tracker, the device model and the section records. A `hardware_timed` command does not cut a block: in channel mode each sample takes the value in force at its own instant (MR-33). Each iteration applies one event, so the loop ends. A wakeup at or before `now` is not scheduled: the loop above has already done what was due.

With several streams every emit and every cut the loop makes is that stream's own, and the loop's work for one instant is done for the streams in their number order, receive before transmit (MR-29).
