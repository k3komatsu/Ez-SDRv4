01 / OVERVIEW

できること

Ez-SDR v4 でできること

SDR実験の条件を保存し、SDR機器をつながずにPC上で動作を試せます。実行条件と結果を一緒に記録するため、同じ環境で実験を繰り返し、条件を変えた結果を比べやすくします。現在使えるのは仮想実験までで、実機接続は計画中です。

実験条件と実行環境を分ける

ExperimentSpec（実験条件）には、周波数やサンプルレート、必要な入出力を書きます。BindingProfile（実行環境）には、使う仮想無線機や周囲の条件を書きます。同じ実験条件を、異なる環境で試せる設計です。

実験条件機器・環境実行前に確認

設計の考え方

AIが実験案を作り、
実行前に条件を確かめる。
設計方針 · AIは実験を組み立て、高速な信号処理は専用の処理が担う
02 / WORKFLOW

実験の流れ

実験条件を確認し、結果を記録する

実行前に、機器が実験条件を満たすかを確認します。実行中の設定や出来事、出力データをまとめて記録するため、後から結果を確かめられます。AIも同じ実験条件を作成・評価できる設計です。

人にもAIにも共通する実験の手順実行前に条件確認 · 実行中は手順を固定
01 · 条件実験条件を書く

周波数、サンプルレート、入出力などを指定

02 · 機器機器と環境を選ぶ

使う仮想無線機や実験環境を設定

03 · 確認実行前に確認

機器が条件を満たすか、動かせるかを確認

04 · 実行仮想実験を実行

現在はPC上の仮想無線機で動作

05 · 記録条件と結果を保存

設定、出力データ、実行中の出来事を記録

仮想実験では、実時間を待たずに時間を進められます。同じ条件を使って結果を確かめ直せます。

DETAILED EXAMPLE · JSON

実験条件をJSONで表す

1 GHz に同調し、毎秒100万サンプルで受信して、10,000サンプルを保存する例です。JSONは実験条件を機械で読み書きする形式です。使う無線機や実験環境は別の設定に分けます。

実験条件の詳しい仕様 ↗ 
{
  "version": 1,
  "requirements": { "vocabularies": [
    { "id": "radio", "major": 1 },
    { "id": "sink", "major": 1 }
  ] },
  "resources": { "radio": {
    "kind": "radio.device",
    "requires": {
      "radio.rx.channels": { "kind": "eq", "value": 1 },
      "radio.rx.sample_rate_hz": { "kind": "eq", "value": 1000000.0 },
      "radio.rx.frequency_hz": { "kind": "eq", "value": 1000000000.0 }
    }
  } },
  "outputs": [{
    "id": "rec", "kind": "sink.capture",
    "feed": { "port": { "component": "radio", "port": "rx" },
      "policy": "drop_oldest", "capacity": 64 },
    "params": { "sink.capture_samples": 10000 }
  }],
  "policies": {}, "extensions": {}
}

PLANNED · PYTHON API

人はPythonで手軽に書く

長いJSONの項目を組み立てず、周波数やサンプル数をPythonで指定する使い方を目指しています。下は設計方針に沿った例で、APIの構文や機能はPhase 6で計画・実装します。

Python APIの設計方針 ↗ 
import ezsdr

with ezsdr.connect() as sdr:
    sdr.rx.frequency = 1.0e9
    sdr.rx.sample_rate = 1.0e6
    samples = sdr.rx.capture(10_000)
03 / DESIGN

システムの構成

実験を支える三つの役割

実験の進行を管理する中心、分野ごとの設定項目、無線機や保存処理などの交換可能な部品に分けています。人もAIも同じ実験条件を使える設計です。

役割 01

実験の進行管理（Kernel）

条件を確認し、実験の開始・停止から、設定や結果の記録までを管理します。

条件確認実行管理結果記録
役割 02

分野ごとの設定項目（Vocabulary）

周波数やサンプルレートなど、無線機やシミュレーションで使う項目の名前と意味を定めます。

無線機シミュレーションデータ保存
役割 03

交換できる機能部品（Modules）

仮想無線機、信号処理、データ保存などを、共通の接続ルールに沿って追加できます。

仮想無線機信号処理ファイル保存

AIエージェントは実験条件の作成や仮想実験の分析を助ける想定です。サンプルごとに時間を守る必要がある信号処理は、AIの応答を待たず専用のプログラムが行います。人向けPython APIと実機接続は計画中です。

再現性 · 02

再現性は同じPC環境が基準

同じビルドと環境なら、同じ設定でシミュレーション結果を再現できます。異なるOSやCPU間では数値データの最終bitまで一致する保証はありません。

シミュレーション仕様 ↗
AIとの分担 · 03

AIは高速信号処理を担当しない

AIエージェントは実験条件の作成や結果の分析を行う想定です。サンプルごとに決められた時間で処理する部分は、AIの応答を待たない専用プログラムが動かします。
