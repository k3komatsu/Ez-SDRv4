仮想無線機で、SDR実験を試して記録する

Ez-SDR v4 は、Python から PC 上の仮想無線機を動かして送受信を試し、実験条件・受信データ・実行記録をまとめて保存するソフトウェアです。実機がなくても始められ、条件を変えた結果を並べて比べられます。条件も記録も機械が読める形式（JSON）なので、人だけでなく AI からも使いやすい設計です（AI-Native）。

01 · 研究者の疑問に答える

まず知りたい四つのこと

SDR を使った実験をしている方が最初に気にする点に、現在の実装に基づいて答えます。

実機なしで試せる？

使える

はい。PC の中で完結します。

Python から仮想無線機に信号を送り、戻ってきた信号を受信できます。無線機間の伝搬（遅延や雑音）や、指定した障害も再現できます。実験時間は実時間を待たずに進められるので、条件を変えた試行を手早く繰り返せます。

条件や結果は残る？

使える

はい。実行ごとに自動で保存されます。

周波数・サンプルレートなどの実験条件、使った環境、実行中の操作履歴、受信データを保存します。受信データは SDR の測定データでよく使われる形式（SigMF）です。「あの結果はどの条件だったか」を後から確認できます。

同じ条件で再実行・比較できる？

使える

はい。同じ PC 環境なら同じ結果になります。

条件を書き換えて繰り返し実行すると、実行ごとに別の記録ファイルが残ります。たとえばゲインを 0・10・20 dB と変えた三つの結果を並べて比べられます。異なる OS や CPU の間では、数値が最後の bit まで一致する保証はありません。

実機で使える？

未実装

まだです。設計を終えた段階です。

USRP などの SDR 実機を操作する機能は、設計を受理し、実装はこれからです。そのため、実機の測定と仮想実験の比較もまだ行えません。

02 · 実験の流れ

条件を確かめてから走らせ、条件ごと記録する

実験条件（ExperimentSpec）と、使う機器・環境を分けて指定します。実行前に「その機器で条件を満たせるか」を確認し、満たせない場合は理由が返ります。そのため、人だけでなく AI も「条件を書く → 検証する → 結果を見て直す」というループを、自分で回せます。これが AI-Native の中心です。

  1. 実験条件を書く

    周波数、サンプルレート、受信するサンプル数など、実験の中身を指定します。

  2. 機器と環境を選ぶ

    使う仮想無線機や、周囲の環境（実行環境）を選びます。

  3. 実行前に確認

    機器が条件を満たせるかを事前に確認します。満たせない場合は実行前に分かります。

  4. 仮想実験を実行

    PC 上の仮想無線機で送受信します。実時間を待つ必要はありません。

  5. 条件と結果を保存

    条件・環境・操作履歴・受信データを、実行ごとにファイルへ残します。

03 · 試してみる

Python で書いて、実行して、記録を見る

下の二つは、リポジトリの python/examples/ に入っている動作する例です。当サイトの作成時に実際に実行して、出力とファイルを確認しました。

複素正弦波を作り、仮想無線機から繰り返し送信して、10 万サンプルを受信します。connect() は実験を実行するプログラム（ezsdr-server）を自動で起動します。

import numpy as np
import ezsdr

# 周期 100 サンプルの複素正弦波（振幅 0.5）を作る
x = np.exp(2j * np.pi * np.arange(1000) / 100).astype(np.complex64) * 0.5

with ezsdr.connect() as sdr:       # 仮想無線機を起動
    sdr.tx.repeat(x)               # 信号を繰り返し送信
    y = sdr.rx.capture(100_000)    # 10 万サンプルを受信

print(f"captured {len(y)} samples, mean power {np.mean(np.abs(y) ** 2):.4f}")
print(f"Manifest: {sdr.manifest_path} ({len(sdr.manifest['action_log'])} logged calls)")

出力例

captured 100000 samples, mean power 0.2449
Manifest: …/ezsdr-runs/session-38976-0/manifest.json (3 logged calls)

受信ゲインを 0・10・20 dB に変えて三回実行します。実験条件は Python の辞書で書き、実行ごとに 10,000 サンプルを取得して、それぞれ別の記録ファイルを残します（examples/sweep.py を読みやすく整形しています）。

import ezsdr

def build_experiment(gain_db):
    """実験条件：指定したゲインで 10,000 サンプルを受信する"""
    return {
        "version": 1,
        "requirements": {"vocabularies": [{"id": "radio", "major": 1}, {"id": "sink", "major": 1}]},
        "resources": {"radio": {
            "kind": "radio.device",                                   # 無線機を 1 台使う
            "requires": {"radio.rx.gain_db": {"kind": "eq", "value": gain_db},  # 受信ゲイン
        }},
        "outputs": [{
            "id": "rec", "kind": "sink.capture",                        # 受信データをファイルに保存
            "params": {"sink.capture_samples": 10_000},
            "feed": {"port": {"component": "radio", "port": "rx"}, "policy": "drop_oldest", "capacity": 64},
        }],
    }

with ezsdr.connect() as sdr:
    for gain in (0.0, 10.0, 20.0):                   # ゲインを変えて 3 回実行
        result = sdr.run(build_experiment(gain), duration=0.02)   # 実験時間 20 ms
        y = result.capture("rec")
        print(f"gain {gain:4.1f} dB: {len(y)} samples, Manifest {result.path}")

出力例

gain  0.0 dB: 10000 samples, Manifest …/session-38990-0/child-0.manifest.json
gain 10.0 dB: 10000 samples, Manifest …/session-38990-0/child-1.manifest.json
gain 20.0 dB: 10000 samples, Manifest …/session-38990-0/child-2.manifest.json

実行すると、こんなファイルが残る

「条件を変えて比べる」の例を実行した後のフォルダです。

ezsdr-runs/session-38990-0/
├─ manifest.json            # 実験全体の実行記録
├─ child-0.manifest.json    # ゲイン 0 dB の実行記録
├─ child-1.manifest.json    # ゲイン 10 dB の実行記録
├─ child-2.manifest.json    # ゲイン 20 dB の実行記録
├─ …_rec.sigmf-data  ×3     # 受信した IQ サンプル
└─ …_rec.sigmf-meta  ×3     # そのサンプルの説明（SigMF）

実行記録（Manifest）は JSON ファイルで、実験条件・実行環境・操作履歴・出力ファイルの一覧・ハッシュ値が入っています。

自分の PC で動かすには

Rust（cargo）と Python 3.9 以降が必要です。

git clone https://github.com/k3komatsu/Ez-SDRv4
cd Ez-SDRv4
cargo build -p ezsdr-server          # 実験実行プログラムをビルド
python3 -m venv .venv && . .venv/bin/activate
pip install -e python                # Python 側（NumPy も入る）
export EZSDR_SERVER=$PWD/target/debug/ezsdr-server
python python/examples/minimal.py

Python 版の配布パッケージ（pip install ezsdr）はまだありません。現在はリポジトリからのビルドが必要です。

04 · 現状と計画

今使えるものと、これから作るもの

実装状況は 2026-09-30 にリポジトリの最新状態で確認しました。「計画中」は、まだ使えないものです。

今使える 実装済み

  • PC 上の仮想無線機周波数・サンプルレートなどの条件を確認し、受信データの欠落も検出します。
  • 仮想環境での伝搬と障害の再現無線機間の遅延や雑音、指定した障害を PC 上で再現します。
  • 結果の保存SDR 測定データ用の形式（SigMF）と、実行記録（Manifest）を残します。
  • 応答する処理の実行Rust 製の処理部品が「PING」を受けて、指定した時刻に「PONG」を返す例を動かせます。
  • Python からの操作送信・受信・条件の変更と繰り返し実行、記録の取得ができます。

計画中 未実装

  • SDR 実機（USRP など）との接続設計は受理済みで、実装はこれからです。
  • 仮想実験と実機測定の比較USRP X310 などの実測と、仮想無線機の結果を照合します。
  • パケット通信との連携パケット処理を OS のネットワーク機能とつなぎます。
  • 信号処理・応答機能の拡張検出した信号に応じて処理し、応答する機能を追加します。
  • GPU・WebAssembly など、対応する計算方式と機器の拡張さらに先の計画です。
AI

AI-Native とは：設計に反映済み

AI を内蔵するという意味ではなく、このソフトウェア自体が AI から使いやすいように設計されているという意味です。AI エージェントは、人と同じ Python の操作と実験条件を使い、まず仮想無線機（SDR エミュレーション）で自分で検証してから、同じ実験条件を実機で動かすという段階を踏めます。実機の接続は計画中なので、現在使えるのは仮想無線機での検証までです。

  • 機械が読める形式実験条件も実行記録も JSON で、その形式（JSON Schema）が定義されています。
  • 理由つきの拒否条件を満たさない操作は、理由とともに拒否され、その拒否も記録に残ります。
  • すべてが記録される操作履歴が残るので、AI が行った実験も後から人が確認できます。

高速な信号処理は、AI ではなく専用のプログラムが担当します。AI は実験の条件づくりや結果の確認といった、その外側で使います。

ここまでの歩み

  1. 実験条件と実行管理条件・時刻・データ形式・記録の土台
  2. 仮想無線機条件確認と、PC 上で動く無線機
  3. 伝搬と再現無線機間の伝搬と、同条件での再実行
  4. 異常検知とデータ保存欠落の検出と SigMF での記録
  5. 受信への応答PING を受けて PONG を返す実験
  6. Python から操作送受信・条件変更・記録の取得

これから

  1. SDR 実機との接続次に取り組む予定。設計は受理済み
  2. 仮想と実機の比較実測との照合
  3. パケット通信連携OS のネットワークと接続
  4. 処理・応答の拡張信号に応じた応答
  5. 計算方式・機器の拡張GPU・WebAssembly など

05 · 使う前に知っておくこと

現時点の制約

実機の測定はまだできない

USRP などの実機を操作する機能は未実装で、実機との比較も行っていません。現在の結果はすべて仮想無線機によるものです。

開発の順序 ↗

再現できるのは同じ PC 環境まで

同じビルド・同じ環境なら、同じ設定でシミュレーション結果を再現できます。異なる OS や CPU の間で、数値が最後の bit まで一致する保証はありません。

シミュレーションの仕様 ↗

導入には Rust のビルドが必要

配布用のパッケージはまだありません。実験実行プログラムをリポジトリからビルドして使います。研究用途の初期版としてお試しください。
