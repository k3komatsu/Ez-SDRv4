01 / WHY

PURPOSE & PRINCIPLES

Ez-SDR v4 が目指すもの

ハードウェアを用意する前に、実験の意図と制約を記述し、ソフトウェア上で動作と再現性を確かめられる実験ランタイムです。

実験の意図と実装を分ける

ExperimentSpec は必要なリソースや操作など「何を試すか」を表します。BindingProfile は、どの Module を使うか、配置や環境をどうするかを決めます。同じ実験の意図を、異なる構成に結び付けられます。

Spec = intentBinding = implementationcompile before RUN

DESIGN PRINCIPLE

ソフトウェアで検証し、
準備ができたらハードウェアへ。

02 / FLOW

FROM INTENT TO EVIDENCE

実験は、検証できる Run になる

Kernel は仕様を検証して実行計画を組み立て、Run のライフサイクルと制御操作を調整します。サンプル処理そのものは各 Module が担います。

ひとつの実験を実行する流れcompile first · no graph mutation during RUN
01 · INTENTExperimentSpec

リソース、契約、実験で行う操作を記述

02 · BINDINGBindingProfile

Module、配置、channel や fault などの環境

03 · COMPILEvalidate → prepare

照合、制約確認、実行計画の構築

04 · EXECUTERun / Session

Kernel が調整し、Module がデータを処理

05 · EVIDENCEManifest

設定、入出力、イベント、再現に必要な情報

時間は整数 tick と有理数のレートで表現します。実験データの時刻は ClockDomain に結び付き、浮動小数の秒数に置き換えません。

03 / BOUNDARY

A SMALL CORE

変化の速さに合わせた三つの層

安定させる契約は Core に置き、実験領域ごとの語彙や実装は追加・交換できるようにします。

TIER 01 · FROZEN CORE

Kernel

時間、Stream Contract、Spec と計画、Run と Session、Module API など、すべての Module が共有する小さな意味モデル。

timecontractscoordinatorsession
TIER 02 · VERSIONED

Vocabulary

Radio や Simulation など、領域固有のリソース・設定・イベントを型と Schema で定義。互換性を保ちながら版を進めます。

radio 1.2sim 1.1sink 1.1
TIER 03 · REPLACEABLE

Modules

Provider、Executor、Sink、Link などの Kernel 契約に沿う実装。Core が特定の無線機や DSP 実装に依存しません。

MockRadiosim-enginehost Linkcapture Sink

三層モデルは設計上の境界です。UHD Provider、Python API、WASM、GPU などは将来の対象で、現時点の実装には含まれません。
