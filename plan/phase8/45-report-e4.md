## 3. 失敗の中身

### 3.1 速さ（`reviews/45e4b-results.md`）

- **E2b の失敗の仕組みは出なかった（VERIFIED）．** どの測定でも，K にも D にも当たらず，時刻に遅れた更新もない．E2b で設定の遅れを生んだ「受信の遅れが枠を占める」結合は，上限を分けたことで少なくとも負荷の軽い状態では起きていない．
- **ただし，その結合が試されたとは言えない（VERIFIED）．** 前もって積んだ履歴は，走り始めの約 100 ms の遅れしか生まなかった．その後の受信の遅れは 0.3 ms 未満で，E2b のときの 20〜100 ms は再現しなかった．履歴を積めば遅れが続くと考えたのは orchestrator の見込み違いである．
- **失敗した繰り返しの形（VERIFIED）．** 間隔を空けて送る場合は，38.5 s から終わりまで約 11 s，遅れが続けて大きい．遅い方の 100 件は，release から 96 µs 以内に `apply` に入り，その中で 1.0〜1.5 ms を使っている．まとめて送る場合は，2 回の短い山（最大 897 µs）がある．同じ測定で今の形が `apply` の中にいた時間は，最大 58 µs．
- **原因（INFERRED，データでは分けられない）．** 候補は二つ．
  - 数秒続く host 側の乱れ．
  - FakeDevice の受信が DSP の履歴を走査する間，装置の lock を持ち続け（`device.rs:1785-1803`），`apply` が同じ lock で待つこと（`:1423`）．走査は履歴とともに重くなる（`:552`）．
  - 今の形が同じ fake と lock で 58 µs に収まっていることは，履歴の重さだけの説明を弱める．ただし，二つの形の繰り返しは時間をずらして交互に走っているので，比べ方は統制されていない（Sol）．

## 4. 実験が見つけたもの（条件の外）

- **設計の穴を DST と Sol が見つけ続けた．** E4 の中だけで，設計メモに次の規則を足した．
  - 上限を，装置ごとの K と chain ごとの D の二つに分ける（§4.5）．
  - 実行役の生成の失敗の扱い（§4.9）．
  - 片付けの前に判断役を join する（§4.9）．判断役の panic の guard が，片付けの判断と destructor の間に割り込むことを，DST が見つけた．
  - 判断役の inbox が送り手を数える（模型と実行役のスレッド．判断役が抜ける条件）．
- **再現の穴は閉じた．** 受け付けの時刻を記録する時点を，world とスレッドの両方で「呼び出しが戻った時点」に揃えた．そのうえで Q1 を許していた仕組みを外し，1 万 seed で一致させた．
- **レビューの数．** E4 の中で Sol は，設計を 4 回，テスト計画を 1 回，コードを 11 回レビューした（E4a1 で 5 回，E4a2 で 6 回）．出た P2 は合わせて 30 件ほどで，P1 は 0 件．そのほとんどは，模型と本当の寿命や順番のずれだった．判断役が抜けるまわりだけで，5 回のやり直しがかかった．
- **自己レビュー．** DeepSeek による自己レビューは，Sonnet の実装に足すものが小さかった．owner の判断で，E4a2 の直しから外した（memory に記録）．
- **大きさ．** brain/ は 21,318 行（E4 で約 4,000 行増えた）．mutation の行は E4 だけで 120 行（E1〜E4 で 404 行）．gate の mutation の段は約 2,400 行，22〜24 分．
- **時間．** E4 は 2026-11-03 夜から 11-04 朝まで，約 12 時間．

## 5. 推奨：前もって決めたとおり実験を終え，§9 の第一の代わりに移る

二つの条件を，二回続けて満たさなかった．特に holdout は，範囲を広げると同じ割合で穴が出た．DST の力が，模型の範囲と粒度でほぼ決まってしまうことを示している．速さの失敗は原因を分けられていない．それでも，前もって決めた規則を結果を見てから緩めれば，この実験の意味がなくなる．

**移った先でしてよいこと**（設計メモ 45 §7 の「失敗したら」，§8 の D9b-1b と #75）：

- 今の形を続ける．判断を純粋な関数として，今のスレッドの中で取り出す（§9 の第一の代わり）．表で試せる遷移が増える．どのスレッドがどの lock の下で呼ぶかの順は，探索できないまま残る．
- #75 の設計メモを書き，D9b-1b を今のコードで行う（それまでの予定）．
- 実験で得た規則のうち，今のコードにも当てはまるものを洗い出して取り込む．候補は次のとおり．
  - 時刻つきの値の枠を，装置の時刻で空ける．今のコードはすでにそうしている．
  - 片付けの前の join の順．
  - 生成の失敗の扱い．
  - 受け付けの時刻の定義．
  - E2b の `u14c`．

**退けた案**：

- **結果を見て基準を緩め，移行に進む**（N05 を外す，負荷の軽い PASS だけを数える，など）：前もって決めた規則を動かすことになる．
- **第 3 回を行う**：計画が前もって退けている．範囲を広げるたびに穴が同じ割合で出ることを，二回の結果が示している．
- **§9 の第二の代わり（同期の部品を差し替えて探索する）に直接移る**：置き換えるかもしれないコードを探索することになり，UHD の中のスレッドは模型にできない．第一の代わりを先にする．
