## 3. Model

### 3.1 Actors and shared resources

| Actor / resource | State | Notes |
|---|---|---|
| Brain | `Brain` value; an inbox (FIFO); the ops of the step in progress | A step is a pure computation from one input; its effects are a list of ops (cell sections and sends), each executed as its own event in order (§3.2). Never calls the device or reads a clock; time arrives in inputs. |
| Settings executor `S` | a FIFO of commands from the brain; the command in hand | One for the instance. Runs one command at a time to completion. |
| RX executor `R_k` | a FIFO of commands from the brain; its loop position; its streamer handle state; the recv in progress (handle, epoch, requested length, timeout, `one_packet`) | One per stream; the only caller of its streamer. |
| Cell `C_k` | phase (`Off`/`Armed(s)`/`Streaming(s)`/`Stopping(s)`), segment, channel set, generation, epoch, plan cut, retiring epoch's latest cut, executor progress (first undelivered sample), in-flight values with their §4.4 state, an obligation revision, quiesce ack | Every access is one atomic event; no actor performs a device event while it holds a cell (I10). |
| Native control lock `L` | free / held by an actor | Taken by S around a settings call, by R around `rx_stop`/`rx_start`/`rx_start_now`, by the clock reader. `mark_lost` takes no lock (`src/uhd.rs:1154-1156`). |
| Lifecycle gate `G` | free / held | Today's `device_gate` (`src/provider/core.rs:1220-1228,1347-1349`), kept by note 45 §4.5 procedure 4: streamer open, close and rate reads are admitted under `G` with a loss recheck inside it; loss publication takes `G`. |
| Failure flag `F` | clear / set | Instance-wide atomic. Published under `G` (`LossPublish`); read without `G` by ordinary checks. |
| Device model `D` | virtual device time `T` (one tick per sample); per front end a DSP FIFO (capacity a parameter, 32 as `DSP_FIFO`) and log; a radio command queue (capacity; a full queue blocks the caller holding `L`; a command's effective time is max(at, last queued, now) as `FakeDevice::apply`); per streamer `next`, `end`, `then`, `origin`; a host buffer per streamer holding received samples (UHD's streamer buffer; partial packets are delivered as UHD does at a stop's tail, and E2's conformance states the depth FakeDevice matches); lost | Semantics from FakeDevice (§1). Returns "not yet" where FakeDevice would wait. |
| Environment | scripted inputs, each with an earliest and a latest time | Stop, value release, plan cancel (restart or channel move), lifecycle requests (restore, next segment), loss, brain panic. |
| Monitor | the oracle's own record: device application history, qualifying receive evidence, publication history, settlement and report history, deadline observations, witnesses | Part of the search state where it affects a later verdict (§3.3); never read by the core. |

### 3.2 Events (the granularity Sol's plan review must approve)

Each line is one atomic event. The harness picks the next event among the enabled ones; per-actor FIFO order and causality (effect after acceptance, completion after effect, arrival after delivery) hold by construction.

- `Tick`: the sample with timestamp `T` is produced, then `T += 1` (the run starts at `T = 0` with no sample produced, so the first `Tick` produces sample 0). For each running streamer, `D` produces that sample, applies DSP consumption to it (head-of-line FIFO as `FakeDevice::drain`: only the front value can be taken, by a sample at or after both its instant and its arrival; equal-time values by successive samples) and appends it to the host buffer; queued radio commands whose time has come leave the queue. Enabled while `T < horizon + epilogue` and while no undelivered environment input has `latest ≤ T` (time cannot pass a mandatory input; an input's window is part of the case's legal schedule). After the last environment input the run continues in real time to a bounded epilogue (each case sets it at least to its latest deadline plus one recv timeout); an actor still waiting at the end of the epilogue makes the run **incomplete**, reported as such and failing the case, distinct from a protocol violation.
- `Env(x)`: an environment input is delivered: to the brain inbox (Stop, value release, plan cancel, restore, next segment), or as an effect (`Loss` marks `D` lost; `Panic(k)` makes the brain's k-th step panic). Enabled in `[earliest, latest]`.
- `B.step`: the brain takes the head of its inbox and computes `step` (pure); its ops queue up.
- `B.op`: the brain executes the next op of the step in progress: one cell section (reservation, Stop booking, epoch advance, pin query) or one send to an actor's FIFO. A cell section's result is fed back to the brain, which computes the remaining ops from it (pure), so a failed reservation or a changed pin never leaves a precomputed send. The next `B.step` waits until the ops are done. (A whole pure computation stays atomic; each access to a shared resource is its own event.)
- `S.take`: S takes the head command; for a timed value, the cell section "queued → taken", or, if cancelled, no call and `Done{Dropped}` queued for delivery.
- `S.check`: S reads `F` before its device call; if set, S discards its FIFO and exits, writing `Abandoned` as the terminal outcome of the command in hand and of each discarded command (a cell section per command; it does not rely on the brain, which may be dead after a panic).
- `S.lock`: S acquires `L` (enabled when free); the value becomes maybe-applied.
- `S.effect(outcome)`: the device call: `D` enqueues the timed command (enabled only while the radio queue has room; otherwise S stays blocked holding `L`). `outcome` ∈ {ok, refused, partial, lost}, branched where the case says.
- `S.unlock`: the call returns; S releases `L`.
- `S.result`: the cell section writing the outcome.
- `S.send`: `Done` enters the brain inbox.
- `R.cmd`: R takes the head of its FIFO at a loop top (start, stop, close, open, plan change, flush, terminate).
- `R.check`: R reads `F`; if set, R discards its FIFO and exits without device calls (receive commands carry no settings outcome; P2 counts settings commands).
- `R.snap`: the cell section copying the plan (epoch, cut, obligation revision) R computes from.
- `R.recv_begin`: R enters `recv` on its handle, recording the handle, the epoch of its snapshot, the requested length, the timeout and `one_packet`.
- `R.recv_end`: the call returns what the host buffer holds (up to the requested length; one packet when `one_packet`), enabled when the buffer has a packet's worth (or the stream's tail), or when `T` passes the recv deadline (timeout), or when `D` is lost (failure).
- `R.publish`: the cell section: if the epoch, cut or obligation revision changed since `R.snap`, nothing is written and R recomputes (counted) from a fresh snapshot, keeping the original recv's handle, epoch and sample identities (a recomputation never relabels old samples as the new epoch); the revision increments on every obligation change (reservation, take, result, cancellation, consumption); otherwise it writes progress, records the consumption computed outside the cell by value identity, and, when progress reaches the cut (or end-now), makes the Stopping transition (close acceptance; cancel queued values; list taken/maybe-applied ones as obligations). Samples of a recv begun under an older epoch publish only up to that epoch's latest cut; the rest is counted as discarded.
- `R.lock` / `R.call(op)` / `R.unlock`: `rx_stop`, `rx_start`, `rx_start_now` under `L`.
- `R.gate` / `R.lock` / `R.lifecycle(op)` / `R.unlock` / `R.ungate`: open, close and rate reads: R acquires `G`, rechecks `F` inside it (set: release and no call), acquires `L` (the native call takes it), calls, releases `L`, releases `G`. Lock order is `G` then `L`; loss publication takes `G` only and never while holding `L`; S and the clock take `L` only; so no wait cycle exists.
- `R.result`: the cell section writing the phase and device state after a call (`Armed`, `Streaming`, `Off`, `Flushing`, `Uncertain`, `Lost`). A brain-commanded stop makes the Stopping transition in the cell before its call (note 45 §4.5).
- `R.send`: a boundary input (first sample, cut reached, value consumed, drain over, finished with its obligation list, quiesced) enters the brain inbox.
- `Clock.lock` / `Clock.read` / `Clock.unlock`: the clock reader takes `L`, reads `T`, releases `L`, then `Clock.send` delivers `Clock(t)` (enabled at scripted times).
- `Timer(d)`: a brain-booked deadline (drain deadline, recv timeout) is delivered as an input; enabled only when `T ≥ d` (never early; the epilogue gives time to reach it). Its delivery is recorded in the monitor (a deadline observation).
- `Loss.gate` / `Loss.set` / `Loss.ungate` / `Loss.mark`: the actor that saw a call return lost first returns from the native call and releases `L` (never publishes while holding `L`), then acquires `G`, sets `F`, releases `G`, then calls `mark_lost` (note 45 §4.5 procedure 4). A lifecycle caller that sees loss while already holding `G` sets `F` inside the `G` it holds (no recursive acquisition), after releasing `L`. A brain panic's guard acquires `G`, sets `F`, releases `G`, calls `mark_lost`.

### 3.3 Search

- **Exhaustive**: depth-first over enabled events with a visited set keyed by the exact simulation state (not a hash), including pending deadlines, the recv in progress, inboxes, ops in progress, and the monitor facts that affect a later verdict. Diagnostic counters (recompute counts, statistics) and event histories live outside the key; the monitor enters the key as a finite summary (per value: disposition, and the identity of any device application and qualifying evidence — value, channel, segment and epoch, matching sample; per command: terminal outcome; publication progress; deadline observations and the drain-ended transition; witness bits). Invariants are checked on every transition's resulting state before the visited-set lookup, so a violating transition into an already visited state is still caught. Each distinct reachable state has every outgoing edge expanded exactly once. Safety invariants are checked on every new state; progress properties on every terminal state (no enabled event). A revisit of a state on the DFS stack is a cycle and a failure: the model has no polling transitions (receives block, the brain is event-driven), so every cycle is a livelock; this is stronger than fair-scheduler progress and is adopted on purpose. Each case records states, transitions and wall time; one sim02 core, 10 minutes; a run cut by a budget fails. No partial-order reduction; a case that does not fit is reported with its counts (note 45 §7).
- **Scheduler contract**: time passes freely while actors are runnable (threads can be delayed), except past an environment input's latest time. Deadlines are therefore claims about the protocol after a deadline is observed, not about physical scheduling: see P1.
- **Witnesses**: every case declares the paths it exists to exercise (e.g. "a restart decision reached with `F` set", "a final flush stop failed and a restore was requested"); each must occur on at least one explored path, or the case fails as vacuous.
- **Seeded**: random walks over the same events, the seeded configuration of §4; 10,000 seeds or 30 minutes on sim02, whichever first; all failures recorded with their seeds.
- **Trace**: every run can emit its event list; a failing trace replays deterministically and shrinks to a minimal one printed in the failure.
- **Budget overrun**: report the configuration, states, transitions, elapsed time, memory, reached and missing witnesses and the unexplored frontier (for case 6, the affected `k`), and keep any counterexample. Never drop a case, narrow a window, merge events, weaken a witness, add an unreviewed reduction or report a partial exploration as passing. The seeded configuration has its own budget (30 minutes or 10,000 seeds).
- **Measure first**: E1b first runs each case's reduced variant at horizons 8, 16 and 24 and reports states and time before the full horizons; the 1,500-line stage sizes are stop-and-report checkpoints, not targets to compress code or weaken cases.

### 3.4 Time and sizes in the cases

`P = 4` samples per packet, one tick per sample, segment origin 0, horizon 48 unless a case says otherwise. The release window, start lead and drain allowance are parameters of the core; the cases set them so that the interleavings of interest are reachable (not today's profile values). Defaults (G14): in-flight bound 4 (E1–E3; E4 replaces it with K = 4 for the device and D = 64 per chain, §11), recv timeout 8 ticks, drain deadline cut + 8, Shutdown after every other environment input once `T ≥ horizon − 8`.

Each case lists its script, the injections the harness may place anywhere in their windows (every position is explored), what the oracles must show, and its witnesses. ## 5. Oracles

Three kinds of fact are kept apart (Sol plan review 3, 4): device application (`D` applied a value to a sample), qualifying receive evidence (a sample the host received, published or not, including drain and flush samples), and publication (samples given to the user). A settings command has exactly one **terminal outcome**: a call result (ok, refused, partial, lost) for a call actually entered, `Dropped` (cancelled before its call), or `Abandoned` (discarded after `F`, written by the executor that discards it). A value's **disposition** is exactly one of: consumed (in its segment, by qualifying evidence), reported (drain or deadline report, `NoReservation`, `left` at finish, loss), cancelled (before take), refused. A call result is recorded once, by `S.result`. A reported `left` value that a later sample consumes gets a separate **leftover consumption** fact; it is not a second disposition.

Safety (checked at every state):

- **I1** An actor whose most recent `F` check (with no device call since) saw `F` set accepts no ordinary device call; ordinary calls accepted after `F` is set are only those whose check came before it (the window note 45 §4.5 keeps).
- **I2** A value becomes taken only if, at its reservation, the cell phase was `Armed(s)` or `Streaming(s)`, its channel belongs to s, the generation matched, s.origin ≤ e < plan cut, and progress < plan cut.
- **I3** No restore, channel move, streamer close/open or next-segment start is issued for a chain with a taken or maybe-applied value (a pin). Outstanding consumption debt after a finished call is not a pin; it is handled by the drain and flush rules.
- **I4** Each value has at most one disposition and each command at most one result; checked when written against the monitor: consumed ⇒ `D` applied it to a sample that is qualifying evidence of its segment; cancelled ⇒ `D` never received it; reported ⇒ no qualifying evidence of consumption existed when it was reported. Applied to a sample the host never received is legal and ends as reported.
- **I5** Stop's cut is never before published progress; R never publishes a sample at or after the latest cut of the epoch the sample belongs to.
- **I6** A recv begun under an older epoch publishes only up to that epoch's latest cut; publication and progress change in one section; the quiesce ack follows it.
- **I7** No reservation succeeds while the phase is `Stopping` or `Off`.
- **I8** Equal-time values are taken by distinct samples, in booking order; one value per eligible sample.
- **I9** No call on a closed streamer handle; no handle is closed after `F` (loss retains handles).
- **I10** No actor performs a device event while holding a cell. By construction in E1 (cell sections are single events; cell procedures take only `&mut Cell`); an oracle from E2 (G13).
- **I11** In-flight values per chain never exceed the bound; beyond it the brain keeps the value held. (E4: replaced by I11′, K over the device and D per chain, with the progress check P6, §11.)
- **I12** No command for a new epoch's streamer or chain (start, close, open) before the old epoch's quiesce ack.
- **I13** No restore of a chain whose device state is `Uncertain` or `Lost`.
- **I14** No lifecycle admission (open, close, rate read) after `F` is published: the recheck inside `G` closes the window that I1 keeps for ordinary calls.
- **I15** No restore of a channel while any chain holds debt or `left` on that channel (note 44 §3.7), including across streams after a move; pin clearance alone does not make a restore eligible.
- **I16** (P1's safety half) Once a drain deadline input is processed, the brain makes the drain-ended transition (stop pending) in that step's ops, whether or not a pin exists; it does not wait for the pin to clear. Checked at the step, not at the terminal state.

Progress (checked at terminal states):

- **P1** After the drain-ended transition (I16), R issues its stop; the stop call itself may wait for `L` (note 45 §4.7), and the run reaches a terminal state within the epilogue. No claim is made about physical time between the deadline and its observation.
- **P2** Every released value has exactly one disposition by the end. A value held and never reserved is disposed when its segment ends: carried to a later segment that covers it, else reported (`NoReservation`); at shutdown every held value is disposed by today's `settle` rule. Every settings command has exactly one terminal outcome.
- **P3** Every actor exits (shutdown completes), or handles are retained after `F`.
- **P4** No terminal state with an unfinished script and a blocked actor, unless the case lists that state.
- **P5** No cycle (§3.3).
