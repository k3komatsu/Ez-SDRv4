## 2. Rate plumbing and the home of g(rate)

**Where the rate enters.** The rate is fixed for a Run (RM-27; the brief). Two facts are in the code:
- Each Provider already knows root ticks per sample when it declares the transmit clock: Mock `prepare` (`ezsdr-mock-radio/src/lib.rs:2128-2136`, `ratio` from `rate_ratio`), UHD `prepare` (`provider/mod.rs:521-522`, `ratio = Rational::new(n, 1)`; the clock is registered at `arm`, `mod.rs:570-571`, and handed to uhd-tx by `Control::new`, `control.rs:222`). The root rate is `core.mcr` on UHD (UR text: one root tick is one master-clock tick, 200 MHz; `core.rs` `mcr: device.master_clock_rate()`) and `ctx.clocks.nominal_rate(root)` on the Mock (`lib.rs:2118`).
- `Bookings` is created before either exists: `TxStream::new` (`lib.rs:234`) and `Streams::with_streams` (`core.rs`, `Core::new` at `core.rs:815`), so the gap cannot be a constructor argument.

**Design (INFERRED where it names an arm site I did not run).**
- `ezsdr_radio::staging`: `pub const CLOSE_GAP: i64 = 3;` and `pub fn closed_short_gap(root_hz: u64, ticks_num: u64, ticks_den: u64) -> i64` returning `max(CLOSE_GAP, ceil(15 × root_hz × ticks_den / (ticks_num × 1_000_000)))` in `u128` integer arithmetic (samples per second is `root_hz × den / num`). It is the only place the 15 µs and the formula exist in non-test code that the Providers share; the FakeDevice keeps its own copy by design (the comment at `device.rs:665-667`). Integer, because `15e-6` is not exact in `f64`; a unit test pins 15 at 1 MS/s so a float version that rounds up to 16 fails (INFERRED that it could; the product happens to be exactly 15.0 at 1e6 in IEEE, checked).
- `Bookings` gets `gap: Option<i64>`. `Default` is removed (the derive at `staging.rs:275`). `Bookings::unarmed()` is the only value without a gap; `Bookings::arm(&mut self, gap: i64)` sets it. `front()` becomes a method (`fn front(&self, start, len, joined)`) so the short-head arm reads `self.gap?`: an unarmed record refuses a finite short head through the existing "front does not fit the clock" refusal (`ok_or(Overlap::Booking)`, `staging.rs:324`) and never books with no guard. `Chain::own_fronts` (`staging.rs:120`) and `remove_head` (`staging.rs:609`) call `front()`, so they take the gap (or become `Bookings` methods).
- Arm sites (the only places): Mock `prepare` beside `declare_sample_clock` for a transmit stream (`lib.rs:2135`; plus the test constructor `lib.rs:2510-2512` that builds `registered` by hand); UHD `Control::new` where `StreamState.clock` is set (`control.rs:222`) and `Core::register_in` (`core.rs:1412`, `#[cfg(test)]`, 60 call sites of `core.register(...)`), which is the arm site of every unit rig; the two rigs that assign `.clock = Some(..)` directly (`core.rs:2127`, `tx.rs:2011`) are covered by a `StreamState` setter or by `register_in`. A second `Bookings` representation of the clock is avoided by deriving the gap from the same `Clock { n }` at one setter, not by storing it elsewhere.
- Callers that read only `stageable()` (idle streams): `control.rs:285`, `differential.rs:585`, `lib.rs:1931`, `tests/timeline.rs:889` use `Bookings::unarmed()`.
- Tests: ~125 `Bookings::default()` in `crates/ezsdr-radio/tests/staging.rs` (grep count below), 2 in `iii.rs` (`:678`, `:1284`). A local helper `fn bookings() -> Bookings` (armed at the 1 MS/s gap, 15) and a rate-parameterised `bookings_at(rate)` replace them mechanically; `iii::head_front(start, len)` gains a rate and builds its `Bookings` through `closed_short_gap`, so the hardware tests read the record, not a constant.

The tests that pin the plumbing: `rm_15_an_unarmed_record_refuses_a_closed_short_head` (staging), the parity rate loop (§4.9) and the UHD owner-front rate loop (§5.1), which fail if a Provider arms with a constant 15 or with the Mock's gap.

## 9. The one-sub-step argument (why the record may be wider than uhd-tx's actual close between F1 and F2)

After F1, for every close the record's front is at least uhd-tx's, which still fronts at `+ 10` (short head), `+ 1` (other closes via `open.next + pad + 1`), `close_start + 3` (two-zero close), `cursor + 12` (abandon):
- **Short head:** record `end + g ≥ end + 10` for every rate on the transmit grid (g ≥ 15 at ≥ 1 MS/s; at 200 MS/s 3000).
- **Long head / joined / continuation close:** record `payload end + 4`; owner `payload end + pad + 1`, `pad ≤ 1`.
- **Two-zero close:** record `cursor + 5` (`stop_sample` and the abandoned repeat); owner `close_start + 3 ≤ cursor + 3`.
- **Abandon:** the owner is already wider than the record (`cursor + 12` vs the record's `cursor + 3`); unchanged by F1 (and D1 keeps it so after F2).
- **Why no test goes red for that:** the only owner/record comparison in code is `tx_close_past_record_front` (`tx.rs:577-589`), which counts owner > record; F1 can only reduce that count. A booking admitted by the wider record starts at or after its front, so the owner has already closed and the FakeDevice (guard still `end + 10 × ratio`) is already past its guard. Tests that read the owner's front (`tx.chain.front()`: `tx.rs:5258`, `:5270`, `:5531`, the recovery tests) are unaffected by F1 because `tx.rs` still fronts at the old values; in the probe I kept them (`10`) and only the record tests went red, as listed in §7.2.
- **Test that would go red if the argument were wrong:** any F1 test of a booking at the record's front on the UHD rig that expects "on time": the parity `s1_parity_*` and `tx.rs` `ur_21_*` rows listed in §7.2 do exactly that at the new values, so a record that was narrower than the owner or the fake would show there as a `TIME_ERROR`.
- **The reverse risk (record narrower than the device) is limited to the abandon (D1/Q2)** and is pre-existing.
