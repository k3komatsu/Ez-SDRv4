## 0. What the code tells me first (decisions this plan rests on)

1. **Device surface.** `Device` (`src/device.rs:156-230`) has no `Partial` outcome and no acceptance instant: `apply` returns `Result<Applied, DeviceError>` (`device.rs:62-88`; `DeviceError` is `{lost, message}`), `Applied` has no "effective" field. The brain's `Outcome` has `Ok/Partial/Refused/Lost` (`cell.rs:23-30`), and `World::s_effect` takes `effective` from the model (`world.rs:987-1013`, `model.rs:170-182`). Production takes `accepted_at` from `self.core.now()` after the call (`provider/control.rs:882`, i.e. a `time_now()` read, which takes `L`). Open questions Q1 and Q2 below.
2. **`Brain::op` takes `&mut [Cell]`** (`core.rs:349`); the brief wants one `Mutex<Cell>` per stream. Q3.
3. **FakeDevice's manual clock is not a virtual clock.** It advances at real speed while no participant is busy and stands while one is (`host.rs:118-130`, `host.rs:260-262`); `advance_for_test` asserts no participant (`host.rs:296-305`). FakeDevice does not model `L` (its `apply` queue wait sleeps with the state lock released, `device.rs:1417-1469`; `rx_stop` takes no lock, `device.rs:1574-1602`), and `mark_lost` only logs (`device.rs:2110-2112`). So S8 must use `ModelDevice`. Public FakeDevice observers exist: `calls()` (`device.rs:927`), `dsp_log(dir, chan)` (`device.rs:1097`).
4. **Precedent for I10.** The crate already counts held guards per thread in the test build (`provider/core.rs:28-68`, `test_support::entered_lock/left_lock`). The oracle copies that pattern for cells; it does not reuse it (different mutexes).
5. **`World` contains pure logic mixed with sequencing** (§4 lists it). The threads must call that logic, so it moves before the threads are written. This is the largest risk to E1's mutation rows and is done first in phase 2 as its own sub-step (gate: all existing tests and E1 rows unchanged).

## 2. Thread runtime (what it is, and what stays shared with `World`)

- Threads: brain `B`; settings `S`; one `R_k` per stream; one clock/timer thread `K` (reads `time_now()` under `L` for `Late` inputs, and delivers `Timer` inputs when time has passed; only `K` and the controller deliver timers).
- Shared state: `cells: Vec<Mutex<Cell>>` taken only through `CellGuard` (counts per thread; dropped before any device call); `F: AtomicBool`; `G: Mutex<()>`; inbox and each executor FIFO as `Queue<T>`; sink `Mutex<Sink>`.
- `B`: loop { wait inbox; `[BStep]`; `brain.step(input)`; while ops: `[BOp]`; take all cell locks in index order and run **one** `Brain::op`; route the outbox }. The Guard ops (`Brain::op` only records them, `core.rs:349-358`) are executed by `run_guard(step)`: `G` lock → set `F` → unlock → `Device::mark_lost`, the same function that the real-panic path calls (S5).
- `S`: loop { `[STake]` pop and `cell.take` on every cell (as `s_take`, `world.rs:925-953`); `[SCheck]` read `F`, `rules::settings_check` (`rules.rs:151-159`); `[SLock/SEffect/SUnlock]` inside `Device::apply` (hooks in `ModelDevice`); `S.result` (`finish_call` on every cell, the Move channel change, terminal to sink); `[SSend]` `Done` to inbox }.
- `R_k`: loop { `[RCheck]` `rules::loop_check` (`rules.rs:138-146`) then command or recv cycle; recv cycle = `[RSnap]` `cell.snapshot()`, `[RBegin]`+`[REnd]` inside `Device::rx_recv`, `[RPublish]` `Cell::publish` under the cell lock (re-snapshot on `Stale` as `world.rs:1129-1186`), boundary sends; commands run their steps (`world.rs:1371-1384`) with `G` around open/close and the recheck of `F` inside `G`; loss publication as the `Pub` steps }.
- Executors reach the device only through `Arc<dyn Device>`; `ModelDevice` is wrapped in `CheckingDevice`.
- Units: 1 tick = 1 sample, packet P = 4, as the cases; `Settings.freq` carries the value id (`fixtures::value` already sets `value = id as f64`, `brain/mod.rs:41-43`); `ModelDevice` maps `freq as u64` to the model's id. `Device::rx_packet_samples` returns P. A recv timeout of `n` ticks is `Duration::from_millis(n)`; the model reads it back as ticks (never wall time).
- `R_k` publishes into `Sink::published: Vec<(stream, epoch, tick)>`; the Kernel is not involved.

## 3. `Event` → thread point table (item 3)

The controller replays one `Event` at a time: it checks that the named actor is parked at the named point, releases only it, then waits until every actor is parked, blocked in a wait, or exited (`quiet`). An actor that parks at a point different from the trace's next event for it is reported as a divergence naming both. Hook = `Hook::at(actor, point) -> Forced` called at every point below; outside forcing it returns `Forced::None` without taking a lock. Thread-local actor identity set at thread start.

| `Event` | Actor, point | Notes |
|---|---|---|
| `Tick` | controller: `ModelDevice::advance(1)` | wakes device condvar; a recv waiter that becomes ready parks at `REnd`, it does not return early. |
| `Env(i)` Input | controller: pushes into the inbox | |
| `Env(i)` Loss | controller: `ModelDevice::set_lost()` + notify | `World` sets `lost` silently (`world.rs:635-640`); threads must be woken, so waiters re-check. |
| `Env(i)` Late / `ClockLock`, `ClockRead`, `ClockUnlock`, `ClockSend` | `K`: points `Lock`, `Read` (inside `time_now`), `Unlock`, then `Send` | `K` starts serving slot `i` on the controller's word. |
| `Timer(i)` | controller: pushes `Input::Timer`; the timer list is `Shared.timers`, filled from `Command::Timer` | `K` does this in free runs (FakeDevice smoke), never in forced ones. |
| `BStep` | `B`, after the inbox wait and before the pop | |
| `BOp` | `B`, before taking the cell locks. A Guard op's `publish` step: `G`/`F`/`mark_lost` run inside this same point | as `world.rs:781-837`. |
| `STake`, `SDiscard` | `S`, after its FIFO wait and before the pop; `SDiscard` = the same loop after `S` has exited | an exited `S` stays as a discarder until its FIFO's sender is dropped (brain thread exit): `World` discards routed commands forever (`world.rs:975-985`). |
| `SCheck` | `S`, at the `F` read | |
| `SLock` / `SEffect(o)` / `SUnlock` | `S`: inside `ModelDevice::apply`, points `Lock` (`L` acquired after), `Call` (the hook returns the forced outcome `o`), `Unlock` (before `L` is released) | Restore and Move have no device effect in `World` but take `L`: `S` calls `Device::apply` (untimed) for Restore and `Device::time_now()` for Move (a null call that takes `L`, cost: none). Listed as a pair in §4. |
| `SResult`, `SSend` | `S`, after the call and before the cell section / the send | |
| `RCheck(k)` | `R_k`, at the loop-top point after its wait; the wait predicate is `rules::next_action` (§4) | `at_end` comes from `Hook::at_end()` (forcing only); free runs have no horizon. |
| `RCmd(k)` | `R_k`, before the command pop | |
| `RSnap(k)` | `R_k`, before `cell.snapshot()` | |
| `RBegin(k)` | `R_k`, inside `ModelDevice::rx_recv`, before `enter_recv` | |
| `REnd(k)` | `R_k`, inside `rx_recv`: after the wait found "ready" (packet, tail, late start, timeout, lost), before the samples are taken | the take happens after release, so a `Tick` between detection and release changes nothing (the controller runs one event at a time). |
| `RPublish(k)` | `R_k`, before the cell lock for the publish | |
| `RLock(k)` / `RCall(k)` / `RFault(k)` / `RUnlock(k)` | `R_k`: inside `rx_start`, `rx_start_now`, `rx_stop` (and `rx_open`/`rx_close` under `G`); `RFault` = `Call` with `Forced::Fault` | |
| `RGate(k)` / `RUngate(k)` | `R_k`, before `G` is taken / before it is released | the recheck of `F` inside `G` follows `RGate`. |
| `RResult(k)`, `RSend(k)` | `R_k`, before the cell section / before the send | |
| `Pub(holder, step)` | `S`, `R_k` or `B`: points `Gate`, `Set`, `Ungate`, `Mark` of `run_guard` / the loss publication | `Mark` = the `mark_lost` call. |

Merged: none. Not-an-event on threads: the DST's `witness_*` bookkeeping (monitor only).

### 17.4 Sol's narrow check (2026-11-02): N1 by participation; this section supersedes the `parked()` description of §17.3
