The cut-pending arm keeps its existing bound (to the cut plus `span`, clamped 1–100 ms), which can exceed one block plus 3 ms when the cut is far. UHD's per-packet timeout behaviour (a call that reads several packets can wait up to the timeout for each, `rx_streamer_impl.hpp:142–197`, as the draft cites) is INFERRED from that source; UR-17 says "the no-cut wait".

The Mock gets one field, `undelivered`, set at one place: where a block is **accepted** (no link answered `Full`) in `emit_rx_until`'s non-full branch (`lib.rs:~604`) and at segment begin (0). A fault and a refusal never move it. It replaces `rx.next` in the abort floor (`stop_at`: `.map(|rx| rx.next)`, `lib.rs:~1220`) and is the tail's `kf`. Change:
  - **Delivery** keeps following the lowered chain cut on **both** paths: after an abort is published nothing past `kf` is delivered, including a receive already in flight (Sol F2: a receive that returns `[3000, 7000)` after the abort is published and before `Shutdown` is read must publish nothing and must not consume the report in a block event).

A plain abort's own End cuts at `kf` and the tail is 0 by the same rule. [v3-dropped] v2's "a unit-test `book` with a future `e` keeps the old rule" and its item-instant `e ≤ now` test. `finish_locked` computes `end_cut` for the clock end and the tail from this rule; `samples()` and `try_end`'s device stop are unchanged.

## 2. Observables (what the tests read) [v2: the emission-order paragraph is dropped]

Rule for the whole plan: #108's symptom is **lateness**, so S2/S3/S13 assert issued instants, not end state: the `applied` row's `issued` against the cut (`applied[..]["issued"]["ticks"]`, row shape `rx.rs:291`), the `timing` row `rx_segment {origin, at}` (`rx.rs:415`, `at` = `core.now()` when the segment's start went out), the device call log, and `stats.rx_before_origin`. A test that checks only "the clock ended at the cut" passes on the buggy code at a late instant. [v2] The origin a test compares against is computed **independently** of the code under test (`ezsdr_radio::timeline::plan` with the rig's terms, or the formula `cut + one call + allowance + lead` pinned by `n5_the_receive_successor_origin_is_old_rate_call_plus_allowance_plus_lead`), not read back from the Provider's own booking.

Events: `events.drain(...)` filtered to `radio.RX_OVERFLOW`, payload via `RxOverflowPayload::from_payload`; every tail case also asserts the event's source node (`<id>/rx/s<k>`) and the nine-byte hot form (`payload.as_array().len() == 9`), as the parity helper `assert_rx_overflow_output` does for block events [v2, Sol F7].

[v2-dropped] v1's claim that "a refused emit is recorded, so 'the event is there and `rejected` is empty' observes 'emitted before the clock ended'": the collector does not consult the clock registry, so no such observable exists (P13).
