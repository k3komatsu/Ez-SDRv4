## 0. The shape the plan assumes (decisions of the implementation, so the tests have a target)

1. `thread_local! PARTICIPANTS: RefCell<Vec<(usize, u64)>>`, entries `(clock identity, id)`. Identity is `Arc::as_ptr(&inner) as usize`; the guard holds a `HostClock` clone, so a live entry's address is never reused (note 51 §4.1).
2. `HostClock::my_id(&self) -> Option<u64>` is the one lookup. Its three callers resolve it **before** locking the state: `sleep`, `wait` (both pass `me` to `park`, which is a free function with no clock handle today) and `acquire_lock`.
3. `drive(&self) -> Driver`: (a) `assert!(self.my_id().is_none())` first; (b) then `self.register()`; (c) then `ParticipantGuard::new` pushes the entry. A real clock: `register()` is `None`, no entry, the `Driver` holds nothing, and a second `drive()` on a real clock does not panic (see §7, point 1).
4. `Driver { _guard: Option<ParticipantGuard>, _not_send: PhantomData<*const ()> }`. It reuses `ParticipantGuard`'s `Drop` (one place for `unregister` and for removing the entry); that Drop removes **its own `(clock, id)` pair** (`retain(|e| *e != me)`), through `try_with` so a drop during TLS teardown does not panic.
5. `UhdRadio::join` (`provider/mod.rs:388-408`): `loop { let seen = host.generation(); if handle.is_finished() || Instant::now() >= until { break } host.wait(None, Some(Instant::now() + 1 ms), seen) }` with `host = core.device.host()` (the clock `spawn` uses) and `until` still `Instant + JOIN_BOUND`.
6. `Driver` is reachable as `ezsdr_radio_uhd::host::Driver` (`pub mod host`); no re-export needed.

Test names below are proposals; host tests take the `m1_drive_` prefix (host.rs has no row-shaped names; `rules.py` TEST_LIKE does not match `m1_…`, so these need no citation checks), the two join tests take `ur_16_…` (TEST_LIKE: they must exist as `#[test] fn` where UR-16's Test line cites them).

Helpers every host test uses (all exist in `host.rs` `mod tests` unless marked new): `participant`, `bounded`, `within`, `joined`, `until_blocked`, `state_of`, `MS`, `BOUND`. New: `only_the_waited_on_clock_sees_the_thread_idle(how, second)` (E9a–c's shared body; the three tests differ only in `how`) and `ids_on(&clock) -> Vec<u64>` = this thread's entries for that clock only (**not** the whole list, so a test is right on a libtest worker or the main thread under `--test-threads=1`), and `refused(f)` = `catch_unwind(AssertUnwindSafe(f)).is_err()`. Every test whose failure mode is a hang runs its body under `within`/`bounded` (a hung mutant fails with a message, it does not hang the suite). The oracles are `State` fields and exact clock-time equalities; the only wall interval used as an oracle is in (1).

## 7. Open points and what the code contradicts

For Sol's review:

1. **Real clock and a double `drive()`.** Q7 says a second registration of the same thread on the same clock panics; **it holds on a manual clock only** (the wording of UR-33 and test 3 says so). On a real clock the guard is a no-op with no entry, so the same nested-helper bug passes on `fake_real` and real rigs and panics only on a manual one. The plan follows the brief (a real clock registers nothing; test 6 asserts a second `drive()` on it does not panic); the uniform alternative (an entry with no id on a real clock, so both panic) costs an `Option<u64>` in the entry list and a branch in Drop. I recommend the no-op; Sol accepted it as consistent with the explicit choice; it is the orchestrator's call (internal design), not the owner's.
2. **Where the refusal is visible.** The refused call's panic message is "this thread is already a participant of this clock"; tests do not assert its text (a text assertion would pin wording, not behaviour).
3. **Rows 14 and 15 are bound kills.** Declared `"kill": "bound"` per Q8.
4. **Rows 11 and 12** were run in the probe (`mut2.log` J11, J12); the final runs go through `remote_mutate.py`.
