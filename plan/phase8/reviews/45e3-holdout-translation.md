# E3 Part 1: the 20 holdout errors as rows

Rows: `holdout-rows.json` (generator `make_rows.py`, build check `check_rows.py`, logs `logs/check-*.log`). A row with `edits` changes several places (several files); a single-error mutant sometimes needs the same decision split across a section boundary. All rows were applied with `anchor.py` (each `old` matches once) in an out-of-tree copy (`~/.cache/ezsdr-fixes/e3copy/w`) and build with `cargo check -p ezsdr-radio-uhd --lib --tests`, no warnings. Paths below are under `crates/ezsdr-radio-uhd/src/brain/`.

Model note for every "outside the cell" error: a cell procedure is one `&mut Cell` call, i.e. atomic. The error can only exist in the model as a split into two world events or two brain operations, so rows H01, H04, H06 and H09 introduce that split (smallest form). That split is the translation, not a disabled check.

| error | translation | why faithful | equivalent alternative |
|---|---|---|---|
| H01 stale reservation | core.rs: `reserve` validates with `cell.clone().reserve(..)` and keeps the value held; the insertion into `in_flight` (no checks) moves to the `Op::Send` that follows (a separate brain op, so R/S events can run between). rules.rs `reserving` also names that Send so the monitor records the reservation. | check and insert are two brain ops with actor events between; the insert does no recheck. | A new `Section::ReserveInsert` op instead of reusing the Send op. Side effect: if the stale insert lands in a `Stopping` cell, `world.rs reserved()` hits `unreachable!` before the oracle runs (a panic, not an oracle verdict). |
| H02 | cell.rs `reserve`: `e >= cut` -> `e > cut`. | exactly the described condition. | none |
| H03 | cell.rs `reserve`: `progress >= cut` -> `progress > cut`. | exactly. | none |
| H04 stale take | cell.rs: `take` returns `Call` for a Queued value without marking it Taken; `start_call` (the `SLock` event, later) marks it MaybeApplied from Queued, Taken or Cancelled. | check at `STake`, mark at the lock, no recheck; a Stopping cancel in between is overwritten. | Keep Taken but let `start_call` also accept Cancelled (leaves the window smaller: take..lock only if Taken marking is kept at take). Chosen form keeps Queued visible to `committed()` during the window, as H04's "settings observed queued". |
| H05 | core.rs `FirstSample`: `Armed(s)` -> `Armed(s) \| Stopping(s)`. | a delayed first-sample notification turns Stopping into Streaming. | none |
| H06 stale stop floor | core.rs: the Stop section (Armed/Streaming branch) computes the cut `stop_cut` (reads progress) and queues a `StopCut` section that writes it (`book_cut`, no progress reread); cell.rs gets the two helpers. | read and commit are two brain ops. Side effect: the world's `shortened` witness (W1c) is taken around the `Stop` op and no longer sees the cut change, so a case may fail on a missing witness instead of an invariant; Part 2 will classify that. | merge the read into the `Input::Stop` step (before queueing) |
| H07 observation as quiescence | core.rs `PlanCancel`: `cell.retiring = None` right after `advance_epoch` (the brain acks at the cancellation). | quiescence tracking dropped at the moment the cancellation is observed. Weak: R is one thread, so an old recv cannot be outstanding when it runs the Plan command; the I6 ack check reads `retiring`, which this row clears in the same step it is set (before.retiring is None), so the oracle cannot see the ack itself. | `Retiring { published: true }` at `advance_epoch` (a pure equivalent: the ack order does not change). |
| H08 stale cut | rules.rs `publish_round`: the plan is computed from a view whose retiring cut is the snapshot's (begin-time) cut. | uses the cut captured at snapshot, not the retiring epoch's latest. Expected equivalent: the stale recheck (epoch/cut/revision) refuses a publish from that snapshot, so the plan is never written. | Also removing the stale check would find it but is a second error. |
| H09 split publish | world.rs: R's publish keeps the cell write as is, then restores `progress` and queues `RStep::Advance(new)` ahead of the boundary sends; the `RSend` event runs the advance as its own event. | publication, boundaries and cut-reached effects happen first; P advances in a later section. Unit tests that assert `progress` after `r_publish` in world.rs may fail first. | change `publish_planned` itself (would trip cell.rs unit tests for a different reason) |
| H10 record before flag | world.rs `PUB_STEPS`: Gate, **Mark**, Set, Ungate. | loss recording before the flag. Limit: nothing in the model reads `marked`, and a call on a lost device never touches it, so no wrong device work is observable. | brain guard order `Gate, MarkLost, FlagSet, Ungate` (it also makes the brain dead early) |
| H11 entry-only check | rules.rs `next_action`: `if failure` -> `if failure && !receiving`. | an executor already in its receive loop no longer exits on the flag; it still records the check that saw F (I1 reads that). | check only at the first iteration of each cycle |
| H12 panic skips mark_lost | world.rs `publish`: `Mark` sets `marked` unless the holder is the Brain. | flag set, native loss mark omitted on panic. Limit: no oracle reads `marked` (witness only). | remove `MarkLost` from the guard list (stops the brain's Dead transition too) |
| H13 pin predicate | cell.rs: `pinned`, `pinned_on` and `committed` no longer count Taken. HO13a: only `pinned`/`pinned_on` (start-next, drain stop). HO13b: only `committed` (restore, move, close, open, flush). | one predicate in three copies; the alt rows give the brief's separate branches. | none |
| H14 finish as settle | rules.rs `settle_call`: after `finish_call` also `cell.retire(id)`. | the executor's result write removes the value; the brain then takes it for an already-settled one and writes no disposition. | `finish_call` writing a new Settled state (needs a new state) |
| H15 partial as rejection | world.rs `s_effect`: terminal `Partial` is written as `Refused` while the device effect stays. | residual obligation (owed debt, left) vanishes; the brain disposes Refused. | map in `Cell::finish_call` only |
| H16 deadline revokes taken | core.rs `TimerFired` (drain Draining): taken and maybe-applied values are removed before the stop is sent. | pin and residual cleared at D; the later completion finds no value. | cancel them into `Done(Abandoned)` instead of removing |
| H17 timeout cleanup | no translation. | the model has no join timeout, no cleanup that closes or drops handles, and no handle-retention decision (shutdown only sends `Terminate`; P3 checks that actors exit). | none; counts as not found unless the orchestrator rules otherwise |
| H18 full cell drops head | core.rs `reserve`: at the bound, the held value is removed and the call returns. | value disappears with no reservation. | none |
| H19 call start for acceptance | world.rs: `SettingsExec.call_at` records `device.t` at `SLock`; `accept_all` gets `effective.min(call_at)`. | consumption threshold is the call's start, not the acceptance instant. | record `at` instead of `effective` |
| H20 prefix consumed | rules.rs `consume_samples`: before the production rule runs for a sample, every value with `reach <= tick` on the carried channels is consumed by that sample. | one sample consumes the whole eligible prefix; the production `RxChain::consume` (outside brain/) is untouched. | change `RxChain::consume` (outside the allowed files) |
