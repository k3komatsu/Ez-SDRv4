# Stage L2 — TX chain test plan (Run 2, amended after Sol review)

**Base:** `main` at `ec3c304` (includes L1). Scope remains behavior-preserving; implementation follows this amended plan. No design text is expected to change.

## Scope and test seam

Move only uhd-tx's device-burst cursor/tail, safe-start front, and recovery state into a private per-streamer `TxChain`. Keep Kernel-burst progress (`Open { held, next, first }`) in uhd-tx and keep `TxChain` owner-local; do not move state into `Core`. Do not change device call order/arguments, records, events, burst flags, timing, or existing test verdicts. Redirect existing direct-field setup/assertions through transitions/accessors; remove or weaken no test.

Use the `tx.rs` unit-test seam, `FakeDevice`, and manual device/host clocks. Integrated tests assert exact call order/arguments, transmitted samples, records/reports, reservations, segment state, streamer generation, and correlations where relevant. Gates synchronize races; their safety timeouts only prevent hung tests and are not verdicts. Registered `HostClock::spawn` participants are permitted to drive manual-clock waits; no test verdict depends on elapsed wall time. `reports()` and `report()` execute on the TX owner—there is no separate report thread writing chain facts. Concurrency is external Stop/loss publication and control-path ownership against that owner. No hardware or dependency/option change.

### In-flight Stop/loss sequences

Add deterministic gated `Tx::pass()` cases, reusing the gate pattern in `core.rs` around 2188–2212. Cover four orderings: Stop after the owner claims the streamer but before the reopen device call; loss at that point; Stop while T3's final ACK `tx_async` return is held; and loss while that return is held. Publish through the real stream/loss path, then release the gate. Assert owner claim is returned, no false `Halted` or refusal cancellation, no experiment payload, and (for loss) no device operation starts after loss was observed. Preserve permitted shutdown/report reads. Use manual-clock registered participants where needed; synchronization timeouts are only hang guards. Do not create a separate report writer: report handling stays on the `Tx::pass()` owner.
