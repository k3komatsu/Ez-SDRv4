# E3 Part 3: the past-bug table (D9b-2 x6, L1 x4)

Facts from `e3-past-bugs-facts.md`; coverage rechecked against the current tree (E1, E2a, E2b; lines are brain/ at the working tree). "Found by the DST" rows were injected as mutation rows in an out-of-tree copy and run exactly as the holdout rows (suite, 13 walk sweeps at seeds 1-10,000, 11 micro searches; sim02/sim03). Results: `holdout-results-raw.md` (rows PB2, PB2b, PB3, PB6, PB7, and HO11), logs `logs/PB*/`.

| bug | verdict | evidence |
|---|---|---|
| D9b-2 #1 stale `stopped` flag demotes a covered successor's retune | **cannot happen in this form** | The brain keeps no `stopped` flag, and a value is reserved only in a cell whose phase is `Armed` or `Streaming` (`cell.rs:231-235`, `Refusal::Phase`); a successor configured but not begun is `Off` (a begin sets `Armed` only when it succeeds, `cell.rs:455-460`), so it cannot receive a value between configure and start. |
| D9b-2 #2 restore after a failed flush stop | **found by the DST** | Row PB2b (restore decision accepts an `Uncertain` chain: both guards, `core.rs:816` and the `phase != Off` wait): `case7b_flush_final_stop_restore_walks` I13 restore of a chain that is uncertain or lost (5,031 seeds; seed 2, 101 events) and `case7b_late_restore_walks` I13 (5,010 seeds; seed 2, 94 events). The one-guard row PB2 (E1-36) fails differently: micro cases 7b and 7b late `Incomplete` (a restore deferred forever), walks `Incomplete`; the second guard turns the restore into a wait. Unit `u17d_flush_final_stop_failure_uncertain_no_restore` also fails. |
| D9b-2 #3 completion races a late hand-over | **cannot happen in this form** | The decision and the close of acceptance are one brain operation: `sent()` calls `stop_accepting()` in the operation that sends the Stop (`core.rs:592-596`), and `reserve` is another operation of the same brain (`core.rs:540-555`), so no reservation lands between a stop decision and its record. Injection PB3 (E1-40: the send no longer closes acceptance) is **not found by the DST** (suite fails only the units `u05c`, `u09x`, `u16d`; walks and micro clean): the reservation that slips in becomes a left value, which no oracle forbids. The structural rule, not a search, carries this item. |
| D9b-2 #4 refused successor leaves handed entries without an owner | **cannot happen in this form** | A value is never handed to an unbegun successor (`cell.rs:233`); a refused begin keeps the phase (`cell.rs:460`) and its boundary only settles the outstanding command (`core.rs:463`). No owner/ownerless-entry concept exists. |
| D9b-2 #5 successor cancelled in `await_release`, refused move destination, shutdown without a stream | **cannot happen in this form** | There is no `await_release`; a Move or Restore waits for every committed value on its channel (`core.rs:831-840`), and shutdown disposes each held value once (`core.rs:491-496`). The per-exit settlement they needed was deleted by L1 in production too. |
| D9b-2 #6 `pending_settled` remembered that settlement ran | **found by the DST** (the class; the flag itself cannot exist) | Row PB6 (E1-79: loss does not dispose the stream's values): P2 "released value has 0 dispositions" in micro cases 2, 7a, 8 (`case2_..._micro_full` 45 events, 3,406 states) and walks cases 2 (595 seeds; seed 29, 117 ev), 8 (354), 7a (607). Dispositions are first-write-wins per value id (`core.rs:388-393`), so a flag standing for "settled" does not exist. |
| L1 M1 cut-free LateCommand restart after a handoff loss calls `rx_start` | **found by the DST** (executor-side injection) | Row HO11 (the receive loop no longer exits on the failure flag while it is receiving): I1 "Rx makes an ordinary device call after a check that saw F set" in micro cases 2, 7a, 8, 6 (stop) and walks cases 2 (9,791 seeds), 7a (9,999; seed 1, 28 ev), 6, 8, seeded. A brain-side injection (PB7, E1-33: a Late after Lost issues a start) is **not found** by the DST: the executor's loop check (`rules.rs:204` `next_action`) exits before the restart (suite fails only unit `u16c_lost_no_call`). So the model is protected by the executor check, and only the check's removal is visible. |
| L1 M3 blocked RX head skips the due-record fold | **not solved** | The model has no records: no `issued` row, no configuration-of-record fold, no head-of-line holding across a stream's values (`Held` is reserved per stream, `core.rs:480`); uhd-control's release pass is outside note 45. The full design (L1's record fold) would have to model it only if the brain takes over the record keeping; as written, note 45's brain does not. |
| L1 receive window (recv begins after loss published) | **not solved, by design** | The window between the loop-top check and the recv call stays: R's program runs `RSnap, RBegin, REnd, RPublish` after one `RCheck` (`world.rs:972`), I1 allows calls whose check came before `F` (45-experiment §5). It is the window note 45 §4.5 keeps ("narrowed, not closed"); the DST cannot flag it and no row is possible without breaking I1. |
| L1 wiring omission (`abandon_unowned` on spawn failure) | **not solved** | The model has no executor creation or spawn failure (search `grep -n "spawn\|abandon_unowned" brain/*.rs` gives test helpers only). The full design needs it (note 45 §4.7 and §4.9, "executors stopped or handles retained", the class of holdout H17). |

Summary: found by the DST 3 (D9b-2 #2, #6, L1 M1 via the executor check); cannot happen in this form 4 (#1, #3, #4, #5); not solved 3 (M3, receive window, wiring omission).
Caveats: #3 and M1's brain-side injections survive the DST, so for those two the protection is a rule (one operation) or a layered check, not search power; M1 counts as found only through HO11, an injection of the executor-side check.
