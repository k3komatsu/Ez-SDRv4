## Summary

Use a proposed TX-only cap of **20,000 samples per channel**, still bounded by `window / 4`. This is 100 µs at 200 MS/s and needs bench confirmation: the measured zero-underrun UHD `benchmark_rate` send was 10,000 samples, while the Module's 20,000-sample repeat still sent 2,000-sample chunks. `DEFAULT_BLOCK_LEN` remains 2,000 and retains its RX meaning. Repeat waveforms shorter than the TX cap are tiled once, when held, far enough to provide a full-cap slice from every original-waveform phase. The tile allocation is **less than 60,000 `Iq` samples per channel** (<480 kB/channel); long waveforms are not copied.

The plan pins exact payloads, cuts, window admission, end-of-burst, grouped channels, copy avoidance, reusable hot-path storage/metadata flags, and burst accounting. UHD 4.10 has no metadata setters: reuse one immutable handle for the repeating combination `untimed, no SOB, no EOB`; create/free other combinations per send. Reuse the pointer vector per streamer. Allocation freedom is a source-review obligation, not inferred from stable addresses; address checks cover storage identity and pointer correctness only. Do not change MockRadio: MR-15 specifies its 2,000-sample simulation blocks independently of UHD's native send-buffer size.

## Decisions and test fixture

- Define a TX-only cap `C = 20_000` samples **per channel**. Keep `chunk = min(C, max(1, floor(window_ticks / clock.n / 4)))`; retain the existing whole-`wanted` window rule except for the device's first SOB. At 200 MS/s the default 10 ms window gives 500,000 samples at `window/4`, so `C` binds. At 1 and 5 MS/s, `window/4` is 2,500 and 12,500 respectively, so it binds instead.
- For original repeat length `L < C`, tile whole periods to `T = ceil((C + L - 1) / L) * L`. This permits a `C`-sample slice even when the modulo-`L` offset is `L - 1`; merely rounding `C` up to a whole number of periods is insufficient for that phase. `T < C + 2L - 1 < 3C`. The bound is per channel and per short-repeat burst; total memory scales with the number of held/open repeats and channel count. Keep the original length for modulo phase arithmetic. For `L >= C`, keep the input allocation unchanged.
- Use a manual-clock `FakeDevice` rig with configurable sample rate and matching sample-clock ratio. For high-rate cases use 200 MS/s (`clock.n = 1` on the 200 MHz root), a frozen clock, and distinct nonzero sample values so wraps and cut boundaries are observable. Continue to use `FakeDevice::calls()` for `tx_send n=… at=… sob=… eob=…`, and `transmitted()` or loopback RX for exact payloads.
- Reuse the TX owner’s per-send slice workspace and parse `ezsdr.stream.cf32` once per owner, outside `send`. Reuse the UHD pointer vector per streamer. Keep the existing streamer call mutex and lock order; no locking redesign in this stage.
- UHD 4.10 evidence: [`metadata_c.cpp`](https://github.com/EttusResearch/uhd/blob/v4.10.0.0/host/lib/types/metadata_c.cpp), `uhd_tx_metadata_make` assigns `*handle = new uhd_tx_metadata_t`, and `uhd_tx_metadata_free` deletes and nulls it. The API declares make/free but no field setters (`crates/ezsdr-radio-uhd/src/uhd.rs:224-225`). Calling make on a live handle would overwrite/leak it; do not attempt metadata-handle reuse.

### Why MockRadio stays unchanged

The Mock does emit TX headers in `crates/ezsdr-mock-radio/src/lib.rs::emit_tx_until`, but this is not a model of `Device::tx_send` packet sizes. Accepted spec 09 MR-15 explicitly defines those simulated blocks as `radio.rx.block_len` (2,000 by default), shortened at waveform wrap/cuts; `tx_blocks` counts those simulation blocks. UHD instead feeds every native send buffer to `BurstTracker` (spec 18 UR-23 / SC-29). Consequently `BurstRecord.blocks` is provider-local block accounting: after TXS, UHD's count follows its larger sends, while Mock's follows MR-15. Preserve both meanings; compare stable burst semantics and sample totals, not the provider-local `blocks` values. Existing parity checks assert records and behavior, not equal native send-size lists.

## Lock note (observed; do not restructure)

`Tx::pass` holds `Core.streams` only for begin/read and end-read sections, dropping it before `reports()` and `step()`. `UhdDevice::tx_send` briefly locks the TX-streamer map to clone its `Arc`, then holds that streamer's `call` mutex across the native send; `tx_async` uses the same mutex. Successful sends update stats/records under `Core.rec`, and burst release uses `Core.held`; those locks are not held across the device call. These are the per-send/turn locks seen; this stage only removes local hot-path allocations and does not change ownership or lock ordering.
