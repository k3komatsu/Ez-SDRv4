## 0. The shape the plan assumes (so the tests have a target)

1. `UhdRig` gets a first field `_driver: ezsdr_radio_uhd::host::Driver` (`Driver` is reachable there; no re-export needed). Rust drops fields in order, so it drops before `radio` and before `_authority` (the last field).
2. **Where the registration is made (a deviation from the brief's wording, decided for the orchestrator to confirm).** The brief says "after the Authority is built". The sketch registers at the *last* step of `with_run`: `let driver = device.host().drive();` after `prepare` succeeds, immediately before `Ok(UhdRig { _driver: driver, … })`. Reason: no fallible step then runs with a live `Driver`, so the constructor has no `Err`/unwind path on which a local-drop order (driver declared after the Authority) would have to be right, and the only order decision left is the struct's field order. This keeps the Authority's 5 s first-read wait (`authority.rs:468`) and `prepare` outside, as note 51 §4.2 wants. Rejected: registering right after `DeviceAuthority::new` (needs the local order and an error-path guard that no test can observe, see §3 row N51B-09).
3. `with_run` starts with `assert!(!config.faults.contains(&FakeFault::TxBlocks), …)` (note 51 §4.3): `TxBlocks` is a permanent *busy* real-time loop in `tx_send` (`device.rs:1782`), which freezes a manual clock for good, so every rig wait would hang. A panic, not an `Err`: the callers `.unwrap()` the constructor.
4. `wait_for_events(what, count, reached)` becomes a call of `wait_for_events_within(what, count, reached, bound)` with `bound = 10 s` (real time, kept). On expiry it writes `infra::infra(…)` (the shared `tests/common/infra.rs`, one `stderr().write_all`) and then panics with today's text. The extra argument exists only so a fixture can expire in 50 ms.
5. No other rig method changes: `settle` (`host().sleep`), `wait_until` (`time.wait_until`: root branch = `host.sleep`, W6), `finish`/`finish_in_place` (`stop` → `UhdRadio::join` = `host.wait` since 1a, W4) are already clock waits (W table §2.3: the rig has no other wait: W1, W3, W4, W7, W10, W11, W6), so a registered driver is idle in each. Doc comments of `settle`/`wait_until` ("a non-participant", `parity.rs:410-417`) change.
6. The rig always forces `ClockMode::Manual` (`parity.rs:354`, unchanged).
