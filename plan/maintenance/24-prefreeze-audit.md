## 1. Put the invariants into the types (mech:invariant-outside-type)

**Covers:** F1, F10, F3, F32, F4, F5, F2.

**Recommendation.** Make the fields private. Each type gets one validating constructor, and its Deserialize goes through that constructor.
- **NodeId:** the only values are `LOCAL` and what the deserialiser produces.
- **ResourceId:** built only by `parse`, `child` or `parent`; read through `node()` and `path()`.
- **ClockRelation:** `new()` checks all of TM-14 (the domains, uncertainty ≥ 0, finite drift and drift_uncertainty ≥ 0, `valid.from ≤ valid.to`).
- **TimePoint and Duration:** `ticks_in(domain)` is the only way to read the integer, which is what T3 already claims.
- **SampleClockHandle:** produced only by `declare_sample_clock`.
- **RelativeBudget:** `new` refuses `ticks ≤ 0`.
- **`register`:** refuses a domain whose `ended_at` is already set.
- **Value:** depth one becomes structural: `Scalar | List(Vec<Scalar>) | Map(BTreeMap<String, Scalar>)`, reusing `contract::Scalar` with a float type that can only be finite. `Constraint` and `CapabilityValue` hold `Scalar`. Selector serialisation uses `?` instead of `unwrap_or_default` or `unwrap_or(Null)`.

**What it deletes:**
- the checks: `check_rid`, `check_local_ids`, the id branch of `check_ids`, the node checks in `register` and `declare_sample_clock`, the checks inside `convert`, MA-37's budget check, `check_nesting`, `is_scalar`, and the scalar half of `check_shapes`;
- the spec text: the "handed in as a Rust value" clauses of SB-1, SB-22f, RS-15 and X7. SB-4 and SB-5 become "the shape is the type", and D91's rejected alternative is now adopted.

**Rejected alternatives:**
- Keep the fields public and add the missing call sites. That is the D91/D106 pattern, and it is the mechanism itself.
- Add schema bounds only (for example `minimum: 0` on clock_relation). That leaves the Rust path open.
- Defer the Value change. After the freeze it means a v2 of 16 schemas.

**What it changes and the risk:**
- Kernel public API and `kernel_surface_allow.txt`.
- About 15 `.path` reads, and about 120 raw `.ticks` reads across crates. This is the widest edit, but the compiler checks it.
- `Value` stops being recursive in 16 schemas.
- `ezsdr-radio-uhd` and `time/domain.rs` are being edited right now, so coordinate with that work.
- Fixtures that nest values will now be refused.

**Size:** L. It splits into 1a (private fields, L because of TimePoint) and 1b (Value, L).

**Why before the freeze:** after the freeze, making a field private breaks every Module, and changing Value's shape means a v2 of 16 documents. #31's vector (reading `.ticks` without its domain) would stay open for all of v4.

## 2. Role-typed identities instead of string prefixes (mech:string-composed-identity, mech:correlation-by-partial-key)

**Covers:** F14, F39 (source half), F13, F15, F17=F26 (#54), F18, F16, F24, F25(f).

**Recommendation.** Write one design note, then make these changes:
- **Typed targets:** `Target = {resource, path} | {output} | {component}`. #54 is then settled: an UpdateParameter verb compiles to its own target, and `sink.capture` names `{output: rec}`. This deletes session.rs:503-534 and Python's `_capture_recorder`.
- **Typed event sources:** `EventSource = {node} | {output} | {island} | {kernel} | {unforeseen}`. The Kernel passes each instance its source root through PrepareContext. This deletes SB-22h, SB-22a's `sink` clause, validation.rs:284-288 and the prefix parsing in `rewrite_spec_target`.
- **`matched` split by role:** `matched` (resources only) plus `needs: {resource: {need: id}}`. This deletes `need_key` and SB-36's collision refusal.
- **PrepareReport loses `fragment`:** the Kernel keys reports by the fragment it invoked, and the Executor receives its fragment id.
- **ActionId reaches the receiver:** `ActionReceiver::recv() -> Option<Dispatched{id, action}>`, and answering payloads carry the id. This deletes the Sink's counters, HD-16's counting text and Python's `_captures`.
- **Undelivered Actions are recorded:** queues hold ActionIds, and FreezeDispatch records the ids it discards (F24 is INFERRED; pin the window with a test first). `submit(Abort)` stops returning a fake `ActionId(0)`.
- **Artifacts carry their producer:** the Kernel stamps each produced artifact with its output, and a repeated id becomes a CleanupFailure.

**Rejected alternatives:**
- Keep the strings and the reserved-segment refusals. The reserved list grows, and D85 says a frozen refusal cannot be loosened.
- Use a separator outside Ident's grammar for need keys. The map would still hold two roles.
- Identify artifacts by hash. Two identical captures (silence, say) share a hash.

**What it changes and the risk:**
- Schemas: event, action, action_template, admission_result, manifest, log_entry and the server frames.
- The Python client protocol.
- The `recv` signature in every Module (MockRadio, UHD, Sink, Executor).
- This is the widest cross-crate change. #54 (S) can land first, using `sink/rec`, if the note lags.

**Size:** L.

**Why before the freeze:** Event.source, Action.target, `matched`, PrepareReport and ActionReceiver all freeze as schema or role-trait shapes. Changing any of them later is a Kernel major or a v2 of several documents.

## 3. One admission path (mech:admission-per-origin, mech:fact-stated-twice-in-spec)

**Covers:** F12, F7, F8, F9, F11, F27, F29, F6, F25(d), F32 (class-lookup half).

**Recommendation.** Rewrite KC-24 as the single admission order and its full refusal table, including rows for `ezsdr.value` and `ezsdr.update_class`. `admit_with` then follows it step by step.
- **Update class:**
  - Remove `class` from `ActionTemplate::UpdateParameter` and `CompileRule::UpdateParameter`.
  - One `declared_class(target, key)` is called at admission, and validate reuses it.
  - `ParamDecl.update_class` becomes `Option`, where None means fixed for the Run. It stays in `component_classes` as an explicit refusal.
- **Keys:**
  - `ExperimentSpec::keyed_entries()` feeds both the prefix check and the KeyDecl check, and covers schedule and outputs too.
  - Admission checks a KeyDecl key's value with `check_value_kind`.
  - `key_decl` returns `Option<&KeyDecl>`.
- **Targets:** take KC-23's set, so a schedule entry may target a component. One `classify_target` is shared by validate and `rewrite_spec_target`.
- **SB-30:** drop "and of its needs' Eq constraints".
- **MA-34 on component param keys:** this needs your ruling. My suggestion: the owner is `ext.<module>.` or a Vocabulary declared by the Executor's Module. That rule is INFERRED; it is the question Phase 5 left open.
- **ASCII keys:** `emit_control` and `Action::Emit` check them too.

**Rejected alternatives:**
- Patch each origin as it is found. That is the mechanism.
- Keep `class` on templates and add a register-time consistency check. That is still a second declaration of a value that has only one legal answer.
- Narrow KC-23 to SB-16's set. It would forbid scheduling what the Session path already allows.
- Narrow MA-34's text. Component keys would stay unowned.

**What it changes and the risk:**
- Schemas: action_template, vocabulary_descriptor, experiment_spec and component_descriptor.
- Spec rules: SB-2, SB-16, SB-30, RS-52, MA-34, KC-23 and KC-24.
- New refusals will break some fixtures. That is intended.

**Size:** L.

**Why before the freeze:** every check this item adds refuses v1 documents that validate today. After the freeze that is a versioned behaviour change (invariant 39), and KC-24's table becomes logged contract.

## 4. The Manifest's failure and provenance record (failure-collapsed, pending-provenance, fact-stated-twice)

**Covers:** F19, F38, F21, F22, F23, F40, F41, F43, F39 (kind half), F25(c).

**Recommendation.** Two parts of this are live bugs, so file and fix them first:
- F19: the `index == 0` loop breaks KC-30. Put KC-30's fault handling in one function shared by stepping and paced.
- F21: cleanup step 6 must drain before it reads `marks`.

The rest is record shape:
- **Failure reason:** `Termination::Failed{stage, reason}`, and `also: Vec<Termination>` records later failures and escalations (not redundant orderly requests). This deletes `Shared::failure` and `ezsdr.failure`.
- **Untyped sections:** `ezsdr.links` becomes a typed `drops` on each link record, and `ezsdr.children` becomes a typed `run.children`.
- **Event payloads:** STEP_LIVELOCK gets one payload shape, and the Kernel event payloads get typed schemas.
- **Fragment.content:** the coordinator reads islands from `placements` instead of re-parsing content, and the Authority fragment's content is namespaced.
- **Kernel event kinds:** they move into the namespace (`ezsdr.EVENTS_DROPPED`, `ezsdr.unforeseen`), and the EventKind grammar requires a dot.
- **EVENTS_DROPPED:** stamped by `drain(at)`, with source `kernel`.
- **`execution_class`:** becomes `Option`, absent when no plan was built.
- **Enum tags:** StopCause and RunState are tagged `kind`, with Policy.kind renamed to `event` and Abort.cause to `message`.
- **Lease:** the Manifest records `{mode, adoptions, released}`, with no token and no monotonic deadline. Adopt log entries carry no token.
- **RS-6 cleanup steps:** generic names, and drop `children` and `cancel_peripherals`. This updates RS-6, RS-9, RS-25 and KA-12, and needs a Vision §53 issue.

**Rejected alternatives:**
- Keep KC-45's "untyped now, a schema is additive later". The freeze cannot lock what has no schema.
- Amend KC-30 to bless the first-fault-only behaviour.

**What it changes and the risk:**
- Schemas: manifest, stop_cause, lease, log_entry and event.
- Spec rules: RS-6, 9, 10, 25, 35, 42 and KC-7, 30, 32, 42, 45.
- Mostly renames and reshaping, so medium-low risk.

**Size:** M, as a bundle of S changes.

**Why before the freeze:** Manifests are stored, hashed and shared. Every one written before this change lacks reasons and marks or carries made-up values, and changing the shape after the freeze is manifest v2.

## 5. Make the freeze's own mechanism workable (OV-10, OV-12, OV-16, SB-47..49, RS-45)

**Covers:** F35, F36, F34, F42.

**Recommendation:**
- **Per-document versions:** each document type gets its own major and supported-version set in place of the global `SCHEMA_MAJOR` and `SUPPORTED_VERSIONS`. Every `from_json` goes through its MigrationRegistry, and `SpecSection::migrated` receives the migrated body together with the original. BindingSection gains `original_version` and `original_hash`. schema_freeze keeps older majors as frozen files checked against a recorded hash, instead of reporting them as stale.
- **Hash basis:** hash the canonical re-serialisation of the parsed and migrated document. This changes OV-17, RS-45 and SB-27's "verbatim" wording, and `rs_45` then tests through the coordinator.
- **Descriptions:** OV-12's immutability covers the schema with `description` and `title` stripped. Then sweep the descriptions once: no Rust links, no "Phase 1", and the cap written as 2^31.
- **F42 (`propertyNames`):** include it only if one schemars transform in `schema::generator()` covers it. Otherwise drop it, since it adds no validation (D94/D95).

**Rejected alternatives:**
- Fix it at the first v2. These names are on the public allow-list, so that fix would itself be a Kernel break.
- Keep hashing the raw submitted JSON. One Spec then has two identities forever.
- Keep descriptions byte-frozen. D95's "grammar lives in the description" escape hatch then doesn't work, and descriptions rot.

**Risk:** every hash in the fixtures changes once, which is acceptable pre-release; log it. Opaque values lose their submitted spelling.

**Size:** M.

**Why before the freeze:** OV-12 applies from the freeze onward, and the first post-freeze change hits all of (a)–(e). As it stands, a Manifest v2 would let a nonexistent Spec v2 through `check_version` (silent reinterpretation). A hash basis changed after the freeze makes old and new Manifests incomparable.

## 6. Stream Contract corrections (spec 02)

**Covers:** F20, F45, F46.

**Recommendation:**
- **DropCarry:** `DataLink::receive() -> Option<(BlockRef, DropCarry)>`, so each carry belongs to its position in the stream. `ContinuityBuilder::push -> Result<(), StreamError>`, and the builder keeps the carry when it rejects a push.
- **Late receive start:** one encoding. TM-13b keeps only the generic rule and the device-miss sentences move to RM-25. SC-13 defines GAP_BEFORE with `lost` on a stream's first block. SC-30 decides whether that becomes a Gap, and one test pins the choice. LATE becomes TX-only.
- **Alignment:** ALIGNMENT becomes a stream-gap qualifier that yields GapCause::Alignment, and UR-19 sets it. Withdraw SC-31a and drop `ChannelGap.cause`.

**Rejected alternatives:**
- Keep LATE's receive meaning and the per-channel Alignment cause "for a future device". Both are closed variants with no producer.

**What it changes and the risk:**
- The DataLink API and ContinuityBuilder; HostLink, the capture Sink, and UHD's rx.rs (being edited concurrently).
- Schemas: gap and continuity_map.
- Spec rules: TM-13b, SC-10, 13, 16a, 20b, 30, 30b, 30c, 31, 31a, RM-25 and UR-19, plus Vision §23 issues.

**Size:** M.

**Why before the freeze:** these are the Link and Sink API, and SC-17 freezes what each flag bit means. Until this lands, every hardware capture with an alignment error records the wrong cause.

## Findings (verified)

- **F1** [invariant-outside-type, VERIFIED, M] NodeId and ResourceId have public fields, so X7 and SB-1 are re-checked at about ten use sites and written into four spec rules  
  *Where:* crates/ezsdr-kernel/src/id.rs:18 (`pub struct NodeId(pub u32)`), id.rs:227-232 (`ResourceId { pub node, pub path }`; the original citation said 236-241); compensating checks at plan/validation.rs:259-271 (SB-22f instance id, tree, arm_after), :309 and :327 (Sink/Executor memory domains), :343 (Authority governs), :636-655 (`check_local_ids`), :680-690 (`check_rid`); session.rs:150-172 (`check_ids`, RS-15); time/domain.rs:240 (`register`) and :346 (`declare_sample_clock`). Spec text: SB-1 (design/03:128, 'the one name type whose fields are public'), SB-22f (design/03:182), RS-15 (design/04), X7 (plan/phase1/00-overview.md:97). Decisions D91 (00-overview.md:1020), which rejected 'private `node` fields (API growth)', and D106 (:1142).  
  *Problem:* The deserialisers enforce X7 (`NodeId`) and SB-1 (`ResourceId::parse`) at the document boundary. Rust callers can still write `NodeId(7)` or `ResourceId { node, path: "a//b" }`, and the `{node, local}` ids (ClockDomainId, MemoryDomainId, IslandId, DataLinkId) have public `node` fields too. To compensate, the Kernel re-checks every slot where a Rust-built id can arrive, and each slot was found separately: D91 for islands and domains, D106 for the action log, SB-22f for Provider trees. A missed slot produces a Manifest that the Kernel's own deserialiser refuses. I confirmed that only tests build a non-LOCAL `NodeId(n)` (spec_binding.rs, run_session.rs:1444/1453, time_model.rs:641). Production code builds ResourceIds only through `parse`/`child`/`parent`. So making the fields private costs no production rewrite beyond adding accessors for the roughly 15 `.path` reads. A related gap: `RunId::from_string` and its derived `Deserialize` accept any string, so a RunId of `5:…` does not pass through X7. That sits poorly with the id.rs:20-21 comment ('every id in every document embeds a `NodeId` … covers them all'), but RunId embeds its node only as text.  
  *Freeze impact:* After v4.0 the public fields are frozen Kernel API. Making them private would then break every Module, so the scattered checks and the four spec clauses that describe them would stay for good. Every id-carrying slot added after the freeze would need its own check, which is how D91 and D106 came about. Lifting X7 for multi-host would also mean finding and loosening every check site, where it could have been one constructor change.  
  *Fix:* Make `NodeId`'s field private, so the only values are `NodeId::LOCAL` and the deserialiser's output. Every `{node, local}` id is then local by construction, while its fields stay public. Make `ResourceId`'s fields private and add `node()`/`path()` accessors; `parse`, `child` and `parent` remain the only constructors. Then delete `check_rid`, `check_local_ids`, the memory-domain, governs, arm_after and tree checks in `check_bindings`, session.rs `check_ids`, and the node checks in `ClockRegistry::register` and `declare_sample_clock`. Drop the 'handed in as a Rust value' clauses from SB-1, SB-22f, RS-15 and X7, and record that D91's rejected alternative is now adopted. Delete the tests that build forged ids, and update kernel_surface_allow.txt.
