# Failure mechanisms

The vocabulary for AGENTS.md §6's three-strikes rule. Bugs are counted by the design mechanism that caused them (GitHub label `mech:<name>`), not by symptom or area (`area:<name>`). Once three bugs share a mechanism, no open bug of it is fixed before a design note; the *Note* column says where that note is.

First classified on 2026-10-07 over issues #1–#62 from their bodies and fix commits, by a Claude Opus subagent, spot-checked against three fix commits. Each classified issue carries a comment with its reason. Review findings are not counted yet.

| mechanism | definition | issues | note |
|---|---|---|---|
| `mech:planned-state-read-as-actual` | A value decided ahead of its instant (a future SampleClock, a candidate configuration, a settings snapshot, a lateness verdict, a nominal playback position) is stored in the slot that represents the present, or reused later as if still true, so whatever happens in between (another change, a Stop, a host stall, an underflow, a timed update) is lost or contradicted. | 13: #3, #6, #8, #20, #21, #33, #35, #49, #52, #53, #57, #61, #64 | Answered by spec 22 VH-2 (plan on receipt, record at the instant), implemented in `87bb265`, which closed #49, #52, #53, #57 and #61; #64 by the owner's decision on the issue (a halted stream has no channel, read from its one timeline line, note 23), 2026-10-09. |
| `mech:radio-rule-implemented-twice` | One Radio Model rule (a cut, an origin, a lattice rounding, a lead, what to emit when a command is cancelled) is implemented separately in MockRadio and the UHD Module from prose, or by two paths inside one Provider, so the copies decide corner cases differently. | 9: #29, #33, #49, #50, #51, #52, #53, #57, #58 | Answered for timing by spec 22 VH-7 (`ezsdr_radio::timeline`, `87bb265`). **Open for event-reporting rules (#51):** decide whether "implement once" covers what a Provider emits when a command is cancelled, before fixing #51. |
| `mech:stream-lifecycle-scattered` | A stream's lifecycle (running, stopping in a tail, ended, awaiting its replacement, carrying a pending loss) is not one explicit state but separate fields and flags (stopped, stopping, end, the existence of an Rx, a pending loss) that each event handler reads or writes for itself, so a handler that arrives in an unanticipated phase acts on a stream that has ended or not begun, or settles a value that a later event invalidates. | 7: #9, #35, #45, #46, #47, #50, #58 | Answered by spec 22 VH-1, VH-3, VH-4, VH-5, implemented in `87bb265`, which closed #46, #47, #50, #58. |
| `mech:invariant-outside-type` | A value's invariant is enforced only by its constructor, at its use site, or by its internal caller's discipline, while the type also offers an unchecked way in (derived Deserialize, public fields, a safe public method), so invalid values or unsound calls reach code that assumes the invariant. | 6: #2, #7, #11, #22, #23, #24 | No open bug; the next one needs a note first. Candidate remedy before the v4.0 Kernel freeze: private fields and a validating `Deserialize` on Kernel time types (`ClockRelation` still has public fields), and an audit of `unsafe impl Sync`. |
| `mech:failure-collapsed-into-value` | A fallible step's outcome is mapped into a type that cannot represent it (an ignored Result, an error turned into None or a saturated value, an error that replaces an already completed result), so a failure looks like an ordinary value (ASAP, no report, a duplicate ID) or a completed result is lost. | 6: #14, #28, #32, #37, #38, #65 | No open bug. #65 (KC-30's fault loop copied into both coordinator drivers, each letting only the first fault end the Run) fixed by note 25's outcome: one function applies KC-30 to a round's or a pass's faults, 2026-10-09. Candidate remedy: no `.ok()` or discarded `Result` at the Device and FFI boundary (Review L's "a failed getter reads as 0" ceiling is the same mechanism). |
| `mech:string-composed-identity` | An identity is derived by concatenating names into a shared string namespace (<output>_<n>, <a>_<b>, sink/<output>), which is neither injective, length-bounded nor typed by role, so a derived name collides with, overflows or resolves to another entity. | 4: #1, #15, #16, #26 | No open bug. Candidate remedy: structured keys per role, strings only at the edge. |
| `mech:correlation-by-partial-key` | A record is matched to its owner by queue position, a self-declared label, or a key missing one of its fields (a handle without its root, ticks without their clock domain, an ACK without its channel, a report without the fragment that was invoked), so it is attributed to, or removes, the wrong owner. | 4: #12, #17, #30, #31 | No open bug. Candidate remedy: every async record carries its full identity (root, ClockDomain, channel, burst, invoked fragment). |
| `mech:pending-provenance-collapsed` | Pending provenance (a link DropCarry, RX error reports, dropped-event escalation flags) is held apart from the record that must carry it and is reduced to one slot or one returned value, or is not handed over on every path that finishes that record, so part of it is lost. | 5: #18, #19, #34, #36, #66 | No open bug. #66 (marks delivered by cleanup's last drain after the artifacts were finalised) fixed by note 25's outcome: the last drain runs in step 6 (step 5, `finalise_artifacts`, since pre-freeze item 4), before the marks are recorded, 2026-10-09. Candidate remedy: the recording owns its DropCarry and one finish function consumes it; pending errors are kept as a list. |
| `mech:fact-stated-twice-in-spec` | One normative fact is stated independently in two places of the accepted specs or schemas (a general and a Provider-specific clause, two collections, a rule and an algorithm), with nothing making one derive from the other, so the two statements contradict. | 4: #39, #41, #43, #44 | No open bug. Answered by spec 20 (KH-1, KH-2, VF-3, VF-6) and spec 22 DA-1 ("one home per topic"). |
| `mech:admission-per-origin` | A check on incoming Spec or Action content is written into one origin's path or one traversal (scheduled Actions, Session Actions, resources[].requires) instead of the single point every input crosses, so another origin or a nested position skips it. | 3: #5, #25, #27 | No open bug. Candidate remedy before the v4.0 Kernel freeze: one `admit()` that every input crosses. |
| `mech:wall-clock-test-oracle` | A test asserts on host wall-clock timing through a wall-clock FakeDevice, so host scheduling delay fails it as if the contract had regressed. | 1: #10 | Closed by #60 (2026-10-13, [plan 30](30-fakedevice-manual-time.md) §15): the smoke set runs on a manual host clock, and the stress grid of §14 has no failure. |

Review findings since the first classification (not issues; counted for the rule): spec 22 steps 2–3 found five bugs in the UHD Module's refusal round trip between uhd-control and uhd-rx — `planned-state-read-as-actual` and `correlation-by-partial-key`, from one cause, the stream's plan held twice. Design note: [23-one-line-per-stream.md](23-one-line-per-stream.md) (accepted and implemented, 2026-10-08). They also found an empty plan that cut nothing (`stream-lifecycle-scattered`) and an orderly cut computed both in the timeline and in uhd-rx (`radio-rule-implemented-twice`).

Bugs since: #65 (`failure-collapsed-into-value`) and #66 (`pending-provenance-collapsed`), both fixed on 2026-10-09 by the outcomes of their notes, [25-fault-and-mark-notes.md](25-fault-and-mark-notes.md).

Review findings in #60 stage A (2026-10-12 to 13; not issues): the manual-clock anchor rule had an exception (the Authority's first anchor, read while the clock ran), which failed a test twice; the exception was removed rather than patched (plan 30 §15).

Review findings in Phase 8 stage 1b-2b (2026-10-17; not issues): five Sol 6.1 findings on one point, when the destination of a channel move may start (the source's release), all `planned-state-read-as-actual` — the source's cut computed at booking and kept in the destination's item went stale when the source's plan changed (a pending segment, a later `start_rx`), reached only the move's own item, was written into `ready` (which also orders bookings against an `End`), and read only the cut the move itself made (a `Stop`-cut segment ending later). The rule was not patched a fifth time: release became its own field, written only by `timeline::Lines`, which re-reads it from the source's current plan after every operation with one general definition (the latest end of the source's segments that hold the channel and began before the move; spec 07 RM-34). Sol's third re-review found nothing further and recommended keeping the structure ([plan/phase8/00-overview.md](../phase8/00-overview.md) §8).

Review findings in Phase 8 stage 1b-4a (2026-10-18; not issues): a Sol 6.1 re-review found a timed command the fake had queued for a front end applied, after a later spec change, to the same front end returning after its deadline — `planned-state-read-as-actual` (the queue settled lazily, against the spec in force when it was read rather than at the command's instant). Fixed by settling under the old spec before a spec is replaced, as spec 22 VH-2 (record at the instant) already answers; no new note. The same review round also found the queue keyed by channel number across a spec change (`correlation-by-partial-key`) and a native handle not freed when a make failed ([plan/phase8/reviews/1b4a-opus.md](../phase8/reviews/1b4a-opus.md)).

Unclassified: #4 and #13 (one-off bugs); #40, #42 and #48 (spec gaps); #54, #55, #56, #59, #60 and #62 (not defects, or decisions).
